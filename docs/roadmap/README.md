# Enterprise Roadmap — video_pipeline_mcp

> Программа доведения проекта до **корпоративного уровня**. Ведётся мультисессионно:
> каждая рабочая сессия закрывает 1–2 воркстрима и коммитится в git с полным отчётом.
> Этот каталог — **вся документация проекта**: `docs/dev/` удалён владельцем (2026-07-05),
> история файлов и решений = git (`git log --follow`, `git blame`) + журнал [`_sessions.md`](_sessions.md).

## Три способа войти в программу

| Хочу… | Иду в |
|---|---|
| понять, **что реально есть на диске** | [`00_reality_check.md`](00_reality_check.md) — замер, актуализируется каждый раз при расхождении |
| **взять следующую задачу** | [`_sessions.md` → RESUME](_sessions.md) (что закрыто, что дальше) → [`16_execution_matrix.md`](16_execution_matrix.md) (блок = фикс + тест + защита) |
| **работать по плану, а не по сессии** | [`01_master_roadmap.md`](01_master_roadmap.md) (воркстримы P/A/I со статусами) → тематический план: [`13`](13_a1_table_loader_plan.md) таблицы · [`14`](14_testing_system_plan.md) тесты · [`15`](15_security_system_plan.md) защита · [`10`](10_pattern_uniqueness_system.md) уникальность · [`05`](05_data_template_media_system.md) данные/медиа · [`19`](19_montage_subsystem_plan.md) монтаж · [`20`](20_studio_plan.md) веб-студия |

Часть планов **не привязана к сессиям** — их можно брать напрямую из таблицы ниже. Обратная связь
обязательна: закрыл шаг плана → отметил его в плане, в [`02_findings.md`](02_findings.md) и в журнале.

## Механика программы

- **Единица работы** — воркстрим (`P1`, `A2`, `I3`…) из мастер-roadmap. Сессия берёт 1–2.
- **3 прогона** (оси ревью, не разовые): `quality` (code-quality), `style/structure` (project-conventions + anti-hardcode), `systems/security` (security-reviewer + test-master). Каждый прогон сеет находки в `02_findings.md`, привязан к измерениям зрелости (`08 §3.1`) и **честно закрывается по `08 §6`** (обмер всех файлов → адаптация GitHub кроме sec → простые тесты + симуляции с чтением консоли).
- **Каждая сессия:** делает работу → обновляет `02_findings.md` + `_sessions.md` → коммит в git с отчётом → обновляет память проекта.
- **Правило истории (обновлено 2026-07-05):** `docs/dev/` удалён → решения→факты пишем в `_sessions.md` + commit-сообщение + память (НЕ в `docs/dev/history_*.md`). Полный ремап — `08_pass_closure.md §1`.
- **Тесты зелёные** до и после каждого изменения (baseline см. `_sessions.md`).
