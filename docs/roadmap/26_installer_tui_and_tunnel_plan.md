## Что есть сегодня (проверять запуском, не по этой строке)

- `install.sh` — линейная установка; выбор роли делегирован `scripts/install_role.sh` (bash `select`).
- `scripts/install_role.sh` — меню `local|server|both`, пишет `config/install.yaml`.
- `core/deploy.role()` — единственный читатель этой декларации; зовёт `run.sh:73`.
- `scripts/configure.py` — этап 2: меню моделей и провайдеров, запускается в хвосте установки.
- `core/transport/tunnel.py` — cloudflared: подъём, готовность по СОБЫТИЮ соединения, супервизор,
  `status()` и `probe()`.
- `scripts/deploy_tunnel_server.sh` — развёртывание серверного конца (Xray VLESS+REALITY) на VPS
  по SSH; по умолчанию dry-run, пароль спрашивает сам `ssh`.

## Что нашли по заданию 3 (компонент диагностики трафика)

**Найден:** `CloudflaredTunnel.probe()` — `core/transport/tunnel.py:476`.

- **Назначение по коду, не по имени:** ходит `httpx` на публичный адрес туннеля СНАРУЖИ и решает,
  кто автор ответа, по заголовку `Server`, а не по коду возврата (`_край_ответил`, строка 467).
  Это и есть наблюдение реального транспортного потока, а не проверка внутреннего состояния.
- **Кто зовёт:** сегодня НИКТО — метод объявлен и не имеет читателя. Половина, которую ревьюер
  читает, мертва (урок «два источника одной правды», память `hard-won-lessons`).
- **Почему годится:** судит СНАРУЖИ и отличает «ответил край Cloudflare» от «доехало до нашего
  процесса» — ровно граница A/B из заданий 2 и 3, без единой правки протокола.
- **Второй источник улики:** `CloudflaredTunnel.status()` (строка 503) — снимок процесса и рёбер.

**Чего в проекте НЕТ** (доказано поиском по `tcpdump|tshark|pcap|scapy|AF_PACKET` — единственное
попадание в `tests/agent_swarm/`, к туннелю отношения не имеет): захвата пакетов. Значит шаг 6
(дамп с обоих концов) — внешний инструмент, его наличие проверяется, сам он не ставится.

## Модель установки (задание 1)

Пользователь выбирает РОЛЬ машины, а не компоненты. Ровно три пункта, строго в этом порядке:

| экран | ставится MCP | конец туннеля |
|---|---|---|
| **Local** — рабочая машина | ✓ | клиентский |
| **Server** — серверная машина | ✓ | серверный |
| **Tunnel** → второй конец на удалённом сервере | ✗ | клиентский |
| **Tunnel** → второй конец на этой машине | ✗ | оба |

`both` остаётся ТЕХНИЧЕСКИМ значением декларации (`tunnel: both`) и пользователю не показывается —
это разрешено заданием 1 §1 дословно.

**Декларация.** `config/install.yaml` объявляет два факта — `mcp` и `tunnel`, — потому что старый
`role: local|server|both` три из четырёх исходов выразить не может (у `Server` = MCP + серверный
конец эквивалента не было вовсе). Старый ключ читается как совместимость и переводится в новую
пару; `role()` остаётся производным, чтобы источник правды был один.

**TUI — `curses` из stdlib (решение владельца 2026-09-10).** Задание просило Textual/Rich, но выбор
роли идёт ДО создания `.venv`, а роль `Tunnel` не должна тянуть venv вовсе. `curses` — механизм из
библиотеки при нуле установки (ось 1a). Прежнее решение «меню — `bash select`» (план 25, 2026-09-09)
этим отменено осознанно.

## Границы (сведённые правила, действуют на ВСЕ шаги)

- **Транспорт не переписываем.** Протокол, формат пакетов, упаковка, криптослой, серверная
  обработка и совместимость концов остаются как есть. Диагностика — отдельная ветка, не основной
  путь; по умолчанию выключена и включается только на время прогона.
- **Существующее переиспользуем.** Новая обвязка ЗОВЁТ установочную логику, а не повторяет её.
  Найденный компонент подключается, аналог ему не строится.
- **Секреты.** Пароль/bootstrap-секрет не пишем в конфиг, лог, терминал, историю оболочки и
  аргументы процесса; после операции чистим, в том числе при отмене и отказе. Хеш не подменяет
  исходный секрет, если протокол ждёт исходный.
- **Уборка.** Временные capture, payload, файлы и креды сносятся после прогона; туннель
  возвращается в обычный режим, и это проверяется, а не предполагается.
- **UI не рассказывает архитектуру.** Внутренние комментарии, планы, номера планов, состояния
  реализации на экран не выходят. Один экран — один вопрос — один следующий шаг.
- **Отказ называет ТОЧКУ.** «Компонент X отсутствует», «служба X установлена, но не запущена»,
  «соединение есть, серверная проверка не прошла» — но не «что-то пошло не так».

## Шаги (каждый — остаток, свой коммит, своя улика)

| шаг | что | улика закрытия |
|---|---|---|
| 1 | **Декларация установки.** `config/install.yaml` объявляет `mcp` + `tunnel`; `core/deploy` даёт читателей, старый `role:` переводится; неизвестное значение — громкий отказ, не тихий дефолт. | прогон читателей по временным конфигам: новая пара, старый ключ, кривое значение → `SCHEMA_INVALID` |
| 2 | **TUI установщика (`curses`).** Три пункта, подменю туннеля, экраны подтверждения; стрелки/Enter/Esc; Ctrl+C возвращает терминал. Неинтерактивный путь через env — для CI. | неинтерактивный прогон каждой из четырёх веток даёт верную пару в yaml; интерактив рисует меню |
| 3 | **Ветвление `install.sh` по декларации.** Ставится ровно объявленное: MCP — только когда `mcp: true`; cloudflared — только когда нужен клиентский конец. Строки о внутренней кухне из вывода убраны. | прогон каждой ветки: `Tunnel` не создаёт `.venv`; в выводе нет «рядом с VPN», «план 24», «ещё не построен» |
| 4 | **Меню после установки.** Запустить · Настройки · Проверить состояние · Выйти. `configure.py` перестаёт быть обязательным хвостом установки и зовётся отсюда. | установка заканчивается меню, а не автозапуском настроек |
| 5 | **QUICK CHECK.** Соединение, серверные компоненты, службы, конфигурация, базовое рукопожатие — на `probe()` и `status()`. Отказ называет точку и следующий шаг. | у `probe()` появляется читатель; сценарий: край отвечает 530 → вердикт «до нашего процесса не доходит» |
| 6 | **FULL TRANSPORT CHECK.** Тестовый payload `VP-MCP-DIAGNOSTIC-TEST` (id, время, контрольная сумма), наблюдение A до серверной обработки и B после, сверка целостности, уборка. Внешний инструмент захвата — проверяется наличие, не ставится. | payload проходит цикл; при отсутствии инструмента — честный отказ с именем инструмента, не тихий пропуск |
| 7 | **Control Center.** Пункт «Туннель»: Состояние · Соединение · Серверные компоненты · Быстрая проверка · Полная диагностика · Логи. Повторяемо. | тот же набор проверок зовётся повторно из меню, без установки |
| 8 | **Боевая приёмка через ТСПУ.** Сквозная проба из РФ там, где сегодня `530`; дамп обоих концов. Требует VPS — интерактивно владельцем. | проба успешна из РФ; вердикт цикла в журнале |

## Что НЕ делаем этой задачей

- Не пишем своё крипто и свою TLS-мимикрию, не меняем протокол ради удобства теста.
- Не выбираем ИИ-модели в установщике: глобально хранится только ПОЛИТИКА выбора
  (Smart/Performance/Quality/Local only/Online allowed/Manual), конкретные модели — уровень проекта.
- Не ставим внешние инструменты захвата пакетов без спроса и не держим захват постоянно.
- Не трогаем VPN на VPS: своя директория, свой порт, свой юнит.
