**🔴 F70 — нашлось живым прогоном, не аудитом кода.** Поднял сервер на новом aiohttp, чтобы доказать, что
транспорт жив; сервер при старте выпустил ключ S9 — и проверка гигиены показала **`instance_key.pem`
в индексе git**. Приватный Ed25519-ключ инстанса лежал в ПУБЛИЧНОМ репозитории с коммита `e6c3732`.
Причина — щель в `.gitignore`: секция «Секреты» ловила `*.key`, а ключ называется `.pem`. Последствие:
вся защита S9 обнулялась — кто угодно мог подписать записи реестра/очереди как этот инстанс, и
`FOREIGN_WRITE` их бы принял. **Фикс:** `*.pem` + имя файла в `.gitignore`, `git rm --cached`, ключ
**ротирован** (подписанных записей в `workspace/` не было — ротация ничего не сломала).
**История вычищена (решение владельца):** «на GitHub по сути должен быть только чистый реп» —
`git filter-repo --invert-paths --path instance_key.pem` переписал все 105 коммитов, force-push заменил
публичную ветку — **и этого оказалось НЕ достаточно**: GitHub продолжал отдавать висящий коммит по прямому
SHA (`raw/e6c3732/instance_key.pem` → HTTP 200 уже ПОСЛЕ force-push). Добито пересозданием репозитория
(`gh repo delete` + `create` + push; 0 звёзд/форков/issues — терять нечего) → тот же URL теперь **404**. Пруф: поиск тела ключа по всем объектам новой истории → пусто, тот же поиск в
бэкап-бандле находит (значит тест не холостой). Первая попытка проверки была НЕВЕРНОЙ — `if git grep … | head`
читает exit-код `head`, а не `grep`, и «нашлось» печаталось всегда; переделал без пайпа.

**Живой пруф транспорта:** 401 без токена · 200 со своим · 57 инструментов · `FILE_TYPE_FORBIDDEN` через
реальный JSON-RPC (защита F68 работает не только in-process).
