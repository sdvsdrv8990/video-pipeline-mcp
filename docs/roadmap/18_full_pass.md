# 18 — Сплошной проход по планам, сессиям и коду (глобальная цель)

> **Это ЖУРНАЛ ПРОГРЕССА, а не план.** Его единственная задача — чтобы обрыв сессии не стоил
> начала с нуля. Любая следующая сессия начинается с чтения этого файла и берёт первый пункт со
> статусом ⬜. Правило: **шаг закрыт только после коммита**; незакоммиченный шаг считается не
> сделанным, даже если код на диске лежит.

## Цель (директива владельца S24)

Пройти по **каждому** файлу планов, по **всем** сессиям и по коду: доделать несделанное, снять
устаревшие статусы, актуализировать документы, чтобы не потерять уже сделанное, и попутно ловить
живые дефекты.

## Как это делается (метод прохода)

1. **Разведка — только на чтение и параллельно.** Утверждения документов сверяются с диском
   ЗАПУСКОМ (`ls`/`grep`/живой прогон), а не чтением соседнего документа. Разведка ничего не
   правит: правки в одном дереве несколькими руками = потерянные правки.
2. **Правки — последовательно и мелкими шагами.** Один шаг = один смысл = один коммит.
3. **Три типа находок разведки, и третий важнее первых двух:**
   - заявлено сделанным, а кода нет → доделать либо снять статус;
   - заявлено открытым, а уже закрыто → записать, иначе работа делается дважды;
   - **сделано, но нигде не записано** → это то, что теряется при смене сессии.
4. Каждый закрытый дефект получает регрессию, **краснеющую при откате фикса** (мутация).
5. Метод сессии — из RESUME: `/engineering-questions` → домен-скил → фикс → тест → `F#` в
   [`02`](02_findings.md) → коммит → запись сюда и в [`_sessions`](_sessions.md).
