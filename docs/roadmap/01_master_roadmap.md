**Закон размещения способностей (актуальная редакция):** новая способность = адаптер
`core/providers/<cap>/` + тонкие инструменты `tools/<category>/` + декларация в `config/*.yaml`
(провайдеры/реакции/шаблоны) + данные в `workspace/`. Ссылка на `config/ops/<category>.ops.yaml`
из прежней редакции снята вместе с A3.

> **F23 — переоценён (S22).** Прежнее решение «строим `config/ops/{filesystem,tables,excel}.ops.yaml`»
> отменено: ops-реестр упразднён как слой. Декларативность осталась там, где она реально работает —
> `config/providers.yaml`, `server_reactions.yaml`, `firewall.yaml`, `config/templates/`; значение в коде
> вместо такой декларации по-прежнему дефект (скил `anti-hardcode`).

> **Как это исполняется (S18):** воркстримы не берутся поодиночке — сессия берёт **блок** из
> [`16_execution_matrix.md`](16_execution_matrix.md) = «фикс `F#` + тест `T#` ([`14`](14_testing_system_plan.md)) + защита `S#` ([`15`](15_security_system_plan.md))».
> Директива владельца: **сначала фиксы**, тест и защита идут в том же блоке, а не откладываются.

## Оценка объёма

Исходная оценка: ~21 воркстрим × 1–2 сессии ≈ 20–30 сессий; после `08 §6` (полный обмер + двухступенчатое
тестирование) floor поднялся до ~39–54. **Факт на S23: 23 сессии, закрыты Фаза 0 целиком и Фаза 1 почти целиком.**
Остаток по объёму смещён в Фазу 2 (продукт) — она не начиналась всерьёз, и именно она осталась дорогой.

## Definition of "Enterprise-ready"

Измеримо — через рубрику зрелости [`07_maturity_rubric.md`](07_maturity_rubric.md) (16 измерений × L0–L4).
Enterprise = **L4 по всем** (или явно принятый минимум L3). Состояние на S23: инфраструктурные измерения
поднялись (CI, packaging, пины, линт, тесты в git, auth-токен, allowlist, провенанс вывода, секреты в канале);
на нуле остаются **observability/audit-trail (DIM-7)** и **эконом-контейнмент (DIM-11)**, продукт (P-ось) —
ниже своей цели. Порядок к L3: **T2 харнесс (F51)** → `I5` (observability+quotas) → остаток `I6`
(OAuth, deploy-hardening) → P-ось → L4 (conformance-gate + supply-chain).

Кратко: продукт (P1–P7) работает e2e; архитектура соответствует README (A1–A6); CI/типы/логи/auth/packaging (I1–I6); покрытие по плану (I7); доки публикуемы (I8); аудит-словарь имеет артефакты (X1) — всё это = поднять измерения `07` до целевого уровня.
