## 1. Имя: что решает владелец

Заказ дал два имени за один день. Улика `У-1` говорит, что второе занято.

- **`ЦИКЛ ПРОИЗВОДСТВА`** — в дереве 0 вхождений. Уникален, ищется одним `grep`, годится машинным именем.
- **`рабочий цикл`** — 2 вхождения в другом смысле. Как машинное имя даёт ложные попадания с первого дня.

**Решение по умолчанию, под которым идёт работа** (владелец поправит одной строкой): машинное имя —
`ЦИКЛ ПРОИЗВОДСТВА`, оно живёт в скилах, сторожах и подписях; «рабочий цикл» остаётся разговорным
синонимом и в машинные имена не попадает. Альтернатива — забрать имя себе, переименовав раздел
`skill-curator` в «Порядок куратора»; цена — одна правка, но оборот речи в инструкции останется.

Фазы метятся `ЦП-1`…`ЦП-7`. Метка `ЦП` в дереве свободна (проверено); `Ф1`–`Ф4` НЕ переиспользуются —
они уже заняты координатами фаз плана и их ловит `comment_guard._task_tag`.

## 2. Фазы цикла производства

Цикл — не лестница. Любая фаза возвращает на любую предыдущую, и возврат — это ФАКТ с подписью,
а не память («обошли трижды» обязано читаться машиной, иначе третий круг никто не заметит).

| Фаза | Предмет | Артефакт, которым закрывается | Есть сегодня? |
|---|---|---|---|
| **ЦП-1 ЗАМЫСЕЛ** | интерфейсы, радиусы, цена, риски, поведение систем ДО и ПОСЛЕ, долгосрочные последствия, узкие места | `замысел.yaml` — ВЕДУЩЕЕ намерение: что появится, а не что изменилось | ✗ нет (`У-4`) |
| **ЦП-2 КАРТА** | поток данных замысла, включая рубежи, которых ещё нет | маршрут со `состояние: замысел` | ✗ нет (`У-2`) |
| **ЦП-3 СИМУЛЯЦИЯ** | ПОВЕДЕНИЕ замысла, исполненное на дублёре, а не прочитанное | сценарий симуляции, КРАСНЫЙ по устройству, с названной причиной красноты | частично: стенд `22` судит клиента и инструменты, но не замысел |
| **ЦП-4 СОВЕТ** | вердикты сторожей по ЗАМЫСЛУ | свод `patrol --замысел` + названная слепая зона плана | ✗ нет (`У-3`) |
| **ЦП-5 ПРАВКА** | сама правка | правка в дереве (видит `git`) | ✓ |
| **ЦП-6 ГЕЙТ** | цикл до кода + все наборы гейтов | `what_if --intent` (три карты дважды) + 8 джоб `ci.yml` по exit-коду каждой | ✓ (с тупиком `У-7`) |
| **ЦП-7 СВЕРКА** | соврала ли симуляция | расхождение «предсказано ↔ вышло» становится НАХОДКОЙ, а не забывается | ✗ нет |

Три артефакта шага (правка · прогон свежее правки · запись решение→факт) остаются в силе на
КАЖДОЙ фазе, а не только на `ЦП-5`. Фаза, которую нельзя закрыть одним прогоном, нарезана неверно.

## 3. Интерфейсы — спланированы, но ещё не написаны

Все четыре опираются на уже существующую машинерию: механизм берётся у себя же, наш слой — политика
(ось 1a). Ни одного нового сторожа не заводится — расширяются четыре существующих.

### 3.1 Карта замысла — один ключ к шести (`17df`)

`tests/routes/routes.yaml` получает седьмой ключ `состояние: факт | замысел`, по умолчанию `факт`.
Шесть нынешних маршрутов не меняются ни на символ.

- `состояние: факт` — семантика сегодняшняя, без послаблений.
- `состояние: замысел` — **проверка переворачивается**. Несуществующий рубеж перестаёт быть отказом
  и становится содержанием: рядом с ним обязан стоять `создаёт:` — кто его родит. Отказом
  становится ОБРАТНОЕ: рубеж замысла, который уже существует, печатается как «замысел догнал
  реальность — переводи в факт». Разрыв адресуется не `F#` (у замысла нет дефекта), а ключом
  остатка: `становится: <ключ>`.
- Обязательный `симуляция:` — имя сценария `ЦП-3`. Замысел без поведения не принимается: именно
  это отличает карту от списка желаний.

Инвариант против свалки: замысел без движения дольше срока печатается долгом, как `*_baseline.txt`
печатает потолок. Замысел, у которого все рубежи существуют, обязан быть переведён или снят.

### 3.2 Совет сторожей на замысле (`ЦП-4`)

`patrol.py` получает род улики **`замысел`**: `patrol --замысел <файл>`. Зоны выводятся из
объявленных путей замысла (их может не быть на диске — это не мешает назвать зону), и совет
печатает три колонки: кто будет судить · чего потребует · **чего не сможет проверить никто** —
слепая зона ПЛАНА. Третья колонка и есть то, ради чего совет зовут до кода.

### 3.3 Цена решения измеряется СНЯТИЕМ, а не пишется прозой (`13a4`)

Комментарий-костыль не нужно запрещать — нужно сделать ненужным. У нас уже есть механизм, который
отвечает «что сломается, если»: цикл до кода. Ему хватает обратного патча.

`what_if.py --снять <файл>:<строки>` собирает кандидата, УДАЛЯЮЩЕГО решение, гоняет три карты и
печатает цену списком покрасневших сценариев и маршрутов. Ответ «что сломается СЕЙЧАС, если снять»
становится измеренным, а не заявленным. Нулевая цена — тоже ответ, и он двойной: решение мёртвое
либо карты его не покрывают; вторая ветка — находка о слепой зоне.

`comment_guard` получает класс **«мольба вместо цены»**: комментарий вида «не удалять», «намеренно
оставлено», «иначе сломается» — это костыль; вместо него называется ключ измеренной цены.

### 3.4 Состав шапки вместо длины (`2c27`) — здесь заказ уточняется уликой

Владелец: «шапка нужна для понимания зоны ответственности, кто этот файл вызывает, кого он
вызывает». Улика `У-5` показывает, что сегодня это есть в 13 % и 21 % шапок, и есть причина не
чинить это прозой: список вызывающих прозой — **второй источник одной правды**, а такие работают
ровно наполовину и гниют молча. Граф вызовов уже считает `_symbol_graph.py`.

Поэтому предлагается форма, которая даёт владельцу требуемое понимание и при этом не гниёт:
шапка объявляет **зону вызова как ПРАВИЛО** («зовётся только из `tools/`», «точка входа —
читателей нет»), а `_symbol_graph` его ПРОВЕРЯЕТ. Расхождение объявления с графом — отказ, как у
любой пары «объявление ↔ читатель». Поимённый список вызывающих печатает машина по требованию
(`_place.py --файл`), в прозе он не живёт.

Классы мусора шапки, названные поимённо (заказ просил «выделить классы»):

1. **код отказа / результат проверки** («доказано подсадкой», «замер», «краснеет») — 14 шапок; дом: журнал сессий и реестр находок.
2. **координата задачи** (`D#`/`F#`/`S2x`/`Ф#`) — 14 шапок; уже ловится `_task_tag`, но в шапке не судится отдельно.
3. **спорное решение и плата за него** («намеренно», «временно», «пока не») — 9 шапок; дом: измеренная цена (§3.3).
4. **пересказ вызовов прозой** — второй источник графа; дом: `_symbol_graph`. ← класса нет ни у кого.
5. **пересказ декларации** — частично ловится `DECL_LINES_MAX`.

Шапка судится составом: одна строка зоны ответственности, одно правило зоны вызова, остальное —
только неочевидное. Всё, что машина умеет вывести, из шапки уходит.

### 3.5 Храповик принятия для заимствованного сторожа (`У-7`)

Тупик griffe снимается тем же приёмом, которым закрыты все свои сторожа: рядом с
`scripts/guards/*_baseline.txt` появляется список ПРИНЯТЫХ изменений поверхности с причиной
и подписью. `griffe` остаётся судьёй слома; принятие становится отдельным осознанным ходом
(`--bless` с причиной), а не отключением сторожа. Без этого `ЦП-5` заблокирован для любой правки,
осознанно меняющей публичную поверхность, — включая добавление кода отказа.

## 5. Этапы (сессии)

Порядок не переставляется: каждый следующий опирается на артефакт предыдущего.

- **Э1 — этот документ.** Имя, фазы, улики `У-1`…`У-7`, интерфейсы, риски, план. Закрыт тремя артефактами.
- **Э2 — карта замысла** (§3.1): ключ `состояние`, перевёрнутая проверка, обе стороны доказаны подсадкой.
- **Э3 — совет на замысле** (§3.2): род улики `замысел`, три колонки, слепая зона плана.
- **Э4 — цена решения снятием** (§3.3) + класс «мольба вместо цены» в сторож текста.
- **Э5 — состав шапки** (§3.4) — после решения владельца по форме.
- **Э6 — `ЦП-7` сверка после работ**: предсказанное против вышедшего, расхождение → находка.
- **Э7 — доска** (`dc21`): порядок и приоритет задач, доказанные циклом.
- **Э8 — храповик принятия для griffe** (§3.5). ⚠️ Блокирует `ЦП-5`; поднимается раньше, если упрёмся.
