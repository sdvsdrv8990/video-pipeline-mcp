## §3. Что проект уже держит — не переоткрывать

1. **След сервера и журнал харнесса — одна форма** (`core/contracts/TrailRecord`, `logs/trail/*.jsonl`).
   Продукт не зависит от памяти разработки: сервер пишет свой след и базу памяти не знает.
   В базу след попадает только ИМПОРТОМ на стороне разработки.
2. **Меньше кода** (директива 2026-08-14, ось 1a). База законна, только если она ЗАМЕНЯЕТ ручные
   разборы у читателей, а не встаёт поверх. Механизм — `sqlite3` из стандартной библиотеки, без новой
   зависимости. Судится счётом: читатели jsonl → одна дверь.
3. **Закрытый словарь живёт в коде** (план `29` §3 №1): новый род стоит правки словаря намеренно.
   В базе словарь — таблица-справочник, которую дверь СВЕРЯЕТ с кодом. Второго хозяина у словаря нет.
4. **Гейт CI читает файлы учёта сторожей** (джоба `comment-guard`: `invariants`, `findings_count`,
   `comment_guard`). Снос потолков или `evidence.yaml` без перевода читателей краснит гейт.
5. **Остаток пишется подписью, а не статусом** (правило 2026-09-02); в базе остаток — ряд подписи
   с ролью, открытость — запрос, а не поле.

## §4. Модель данных — черновик под заказ «ID, колонки, разбор инструментом»

Каждая таблица имеет ID-колонку; ссылки между таблицами идут по ID, не по пути и не по тексту.

| Таблица | Ключ | Колонки | Заменяет |
|---|---|---|---|
| `entity` | `id` (`<role>.<domain>[.<part>]`) | `kind`, `status`, `superseded_by` | ключи-пути в картах и объявлениях |
| `entity_path` | `id` + `path` | `since_commit`, `until_commit` | переименования, которые сегодня рвут историю |
| `decision` | `id` | `ts`, `who`, `text`, `forecast`, `supersedes`, `stamp` | директивы владельца, развилки |
| `lesson` | `id` | `text`, `condition`, `check_cmd`, `stamp` | уроки метода |
| `run` | `key` (ключ подписи) | `ts`, `kind`, `role`, `intent`, `head`, `dirty`, `zone`, `cmd`, `closes` | `stamps-*.jsonl`, `tails.jsonl` |
| `step` | `run` + `ord` | `name`, `mechanism`, `outcome`, `reason`, `effect`, `entity` | росписи шагов |
| `condition` | `run` + `ord` + `name` | `expected`, `actual`, `matched`, `decides` | наборы условий шага |
| `ratchet` | `axis` | `ceiling`, `moved_by` (ключ подписи) | `*_baseline.txt` |
| `session` | `id` | `title`, `text`, `commits` | журнал сессий |

Проекции, ради которых база и нужна, — запросы, а не таблицы:
- **паспорт сущности** — `entity` ⋈ `step` ⋈ `run` по `entity`;
- **какой набор условий разводит PASS и FAIL** — `condition` сгруппировать по сущности и набору;
- **открытые остатки** — `run` с ролью `ОСТАТОК` без закрывающей подписи;
- **потолок двигался без улики** — `ratchet.moved_by` пуст.

Дамп — по файлу на таблицу, ряды отсортированы по ключу: diff показывает смысл, слияние решается
построчно. Место дампа в дереве решается по `project-conventions` на Э2.
