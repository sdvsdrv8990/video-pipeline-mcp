# 16 — Матрица исполнения: фикс + тест + защита в одном блоке

> Зачем: в `_sessions.md` накопился хвост «что ещё надо», находки живут в `02`, тест-программа в `14`,
> защита в `15` — четыре списка, которые легко исполнять вразнобой. Этот документ **сшивает их в блоки**:
> один блок = одна-две сессии = **проблема закрыта + тест на неё написан + защита продвинута**.
>
> **Директива владельца (2026-08-11): сначала фиксы.** Внутри блока порядок жёсткий:
> **(1) фикс проблемы → (2) тест, который краснеет при откате фикса → (3) защитный/инфра-инвариант.**
> Тест-система и защита развиваются **параллельно** с фиксами, а не «когда-нибудь потом».

## Регламент блока (чтобы не разъезжалось)

1. **Открыть блок:** `engineering-questions` по типу задачи → перечитать соответствующие `F#` в `02` и зону
   теста в `tests/CATALOG.md`.
2. **Фикс первым.** Правка — по домену (`mcp-developer` / `reactions-errors` / `anti-hardcode`).
3. **Тест сразу за фиксом**, в ХОЗЯИНА зоны (не плодить набор). Обязательна **мутационная проверка**: откатить
   фикс → тест обязан покраснеть → вернуть. Результат — строкой в `CATALOG §F`.
4. **Защита/инвариант** — этап `S#` блока; для security-этапа приёмка = симуляция с чтением консоли (C2).
5. **Закрыть блок:** обновить `02` (статус F# + пруф), `CATALOG §E/§F`, `_sessions.md`, коммит с отчётом
   (что/почему/регрессии/F#), убедиться, что CI зелёный (`gh run list` — урок F48).
