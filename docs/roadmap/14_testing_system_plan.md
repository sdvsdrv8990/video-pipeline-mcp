### F50 — `pytest` даёт ЛОЖНЫЙ ЗЕЛЁНЫЙ (пруфы)

```
$ pytest tests/quick/test_audit_fixes.py -q     → no tests ran        # 44 регрессии НЕВИДИМЫ
$ pytest tests/virus_injection tests/bot_army   → 7 passed in 0.01s   # 27 проверок «прошли» за 10 мс
$ pytest tests/quick/test_structure.py -q --collect-only → no tests collected in 0.71s
```

Механика: `check(name, cond)` кладёт `bool` в список и **никогда не ассертит** — гейт живёт в `main()` под
`if __name__ == "__main__"`. Под pytest функция `test_*` отрабатывает без единого `assert` → PASS при любом
исходе проверок. Script-наборы (`structure`/`tables`/`search`/`inventory`/`materializer`) вообще не отдают
тест-функций: их тело исполняется **в момент коллекции**, результат к отчёту не привязан.

Это класс F48 («гейт добавлен ≠ гейт зелёный»), только наоборот: **зелёный, который ничего не проверил**.
Пока раннер не канонизирован, любой `pytest` в CI/у контрибьютора — обман.

## 3. Целевая архитектура тест-системы

```
pytest (канонический раннер, xfail_strict=true)
├── conftest.py            общие фикстуры: repo_root · tmp_workspace · firewall_reset
├── harness/               ЖИВОЙ сервер: спавн на свободном порту · JSON-RPC клиент /mcp · захват консоли
├── quick/                 C1 — unit/contract/регрессии D#/F# (in-process, быстро)
├── <sim>/                 C2 — adversarial-симуляции против живого сервера + ассерты по консоли
├── structure_emulation/   E-A…E-C (реальная работа ИИ со structure_*)
├── agent_swarm/           рой: patterns.yaml (36) + раннер, honest+attacker в одном прогоне
└── eval/                  качество (relevance/поток данных) — opt-in, вне гейта
```

Маркеры: `live` (нужен поднятый сервер) · `sim` (адверсариал) · `slow` · `eval` (opt-in).
CI: `pytest -m "not eval"` — харнесс поднимает сервер сам, cloudflared не требуется; `eval` — отдельная ручная джоба.

## 5. Что НЕ меняем (правила остаются)

- **Не плодить.** Новый постоянный набор — только когда сценарий вне зон ВСЕХ существующих И запас хозяина
  исчерпан (`CATALOG` §правило). Реально новых на горизонте: `harness/`, `structure_emulation/`,
  `agent_swarm/test_agent_swarm.py`, `eval/`. Всё прочее — сценарии внутри существующих зон.
- **Тест = сценарий реального поведения**, не проверка кода. Поведенческий → против ЖИВОГО сервера.
  Мок — только истинно внешние провайдеры (litellm/stable-ts), никогда как замена запуску сервера.
- **Ассерт на контракт:** `ToolResult.status/facts`, `ErrorDetail` + конкретный код `server_reactions` — не truthy.
- **Docstring теста — одна строка** (+`D#`/`F#` для регрессии). Рацио и «5 вопросов» — в commit-сообщение
  и `_sessions.md`, не в исходник (директива владельца 2026-07-05).
- **Честный стаб обязан кричать** (G16): `NotImplementedError`-код реакции, не фейковый `success`.
- **Открытая находка = `xfail(strict)`** `[OPEN-CONFIRMED F#]`, baseline остаётся зелёным; «внезапно прошло» =
  сигнал обновить `CATALOG §E` ⬜/🟡→🟢 и перевести в регрессию.

## 6. Definition-of-Closed для I7 и подъём зрелости

I7 закрывается по `08 §6` — не «тесты написаны», а:

| Ступень | Что значит для I7 | Даёт этап |
|---|---|---|
| A — обмер | тест-система обмерена, дыры → F50–F53 | ✅ сделано (§2) |
| B — готовые решения | pytest/coverage/conformance взяты как готовые, уложены под конвенции (безопасность — из `06`, не с GitHub) | T0/T1/T7 |
| C1 — код-пруф | каждая находка/фикс подтверждена простым тестом | T0 (без раннера C1 недоказуем) |
| C2 — реал-пруф | симуляции реальными инструментами против живого сервера **с чтением консоли** | **T2** — сегодня структурно невозможен |

**DIM-6 (тестирование):** сегодня L1–L2. `T0+T1+T2` → честный L2 (гейт реален, покрытие измеримо, C2 возможен);
`+T4+T6+T7` → **L3** (conformance в CI, рой не декларативен, E-матрица есть); `+T8` и продукт → L4.
**DIM-1 (conformance)** поднимается T7. До ступени C уровни в `07` не двигаем.

## 7. Риски

| Риск | Митигация |
|---|---|
| Миграция на pytest ломает зелёный baseline | T0 = **мост** (`assert main() == 0`), `__main__` сохранён; идиоматичная переписка — по мере касания набора, по одному, с прогоном до и после |
| Харнесс живого сервера делает тесты флаки (порты, гонки, состояние firewall) | свободный порт из ОС, свежий tmp-`workspace/` на тест, гарантированный teardown, `firewall_reset`-фикстура; флак → карантин + чинить корень, не «прогнать до зелёного» |
| Покрытие превращается в самоцель | порог — ratchet от факта, а не «80% потому что круглое»; дыры трактуем по `03` (слои), не по процентам |
| Рой/eval съедают время и токены | рой — детерминированные паттерны из `patterns.yaml`, без LLM; eval — синтетика + локальные модели, opt-in вне гейта |
| E-матрица упирается в непостроенный продукт (Ф3/провайдеры) | всё непостроенное = `xfail(strict)`-spec со ссылкой на F# — фиксируем требование, не блокируемся |
