# Тесты: структура и инструкции

## Назначение

Тест = **сценарий реального поведения**, а не проверка кода. Mock-only тесты «на отвяжись» запрещены.

> **📓 Перед созданием любого теста читать [`CATALOG.md`](CATALOG.md):** зоны ответственности каждого набора,
> запас расширения, правило «не плодить» (сначала расширь существующий), реестр `F#`→тест (§E) и
> **мутационные пруфы** (§F — какой тест что реально ловит).
> Стратегия и E-матрица — `docs/roadmap/03_testing_plan.md`. Машинерия (раннер, харнесс, покрытие) —
> `docs/roadmap/14_testing_system_plan.md`. Порядок работ — `docs/roadmap/16_execution_matrix.md`.

## Структура (факт)

```
tests/
├── README.md                    — этот файл
├── CATALOG.md                   — реестр зон + §E находки + §F мутации
├── conftest.py                  — общие фикстуры
├── test_suites.py               — ЕДИНЫЙ ГЕЙТ: находит наборы сам, гоняет каждый подпроцессом
├── quick/                       — быстрые: unit / contract / регрессии D#/F#
│   ├── test_audit_fixes.py      — дом ВСЕХ регрессий D#/F# (постоянный)
│   ├── test_tools_inventory.py  — контракт tools/list против эталона (постоянный)
│   ├── test_tunnel.py           — регрессия туннеля, оффлайн (постоянный)
│   ├── test_firewall.py         — интеграция, нужен ЖИВОЙ сервер (маркер live)
│   ├── test_search.py · test_structure.py · test_tables.py · test_table_materializer.py
│   └── tools_inventory.golden.json — эталон инвентаря (обновляется только --bless)
├── bot_army/ · cache_injection/ · cache_overflow/ · config_change/ · virus_injection/
│                                — adversarial-симуляции (Security/System)
├── render_draft_final/          — workflow-набор (провайдеры = честные стабы)
└── agent_swarm/                 — patterns.yaml (36 паттернов); раннер — этап T6
```

## Типы тестов

1. **Быстрые** (`quick/`) — гипотеза: создал → запустил → **удалил**. Исключения (постоянные):
   `test_audit_fixes`, `test_tools_inventory`, `test_tunnel`.
2. **Постоянные** (`tests/<name>/`) — регрессия и безопасность, живут в проекте: `test_<name>.py`.

## Запуск

```bash
pytest -m "not live"          # весь гейт (как в CI): наборы находятся автоматически
pytest -m sim                 # только adversarial-симуляции
pytest -k structure           # один набор по имени
python3 tests/quick/test_structure.py   # набор напрямую: exit 0 = ok
```

⚠️ Наборы — самостоятельные скрипты со своим счётчиком; их внутренние `test_*`-функции **не ассертят**.
Поэтому pytest собирает только `test_suites.py` и проверяет **exit-код** каждого набора в подпроцессе
(F50: раньше голый `pytest` давал ложный зелёный). Пофайловая миграция в идиоматичный pytest — по мере
касания набора; тогда файл добавляется в `python_files` (`pyproject.toml`).

## Порядок работы с тестом

```
1. CATALOG.md — чья это зона? расширяем хозяина, а не плодим новый набор
2. git log --follow <файл теста> — что уже чинили здесь (история = git, не history.md)
3. Исходник теста — какие сценарии уже покрыты
4. Пишем сценарий, ассерт на КОНТРАКТ (ToolResult.status/facts, ErrorDetail + код server_reactions)
5. Прогон + МУТАЦИЯ: откатить фикс/защиту → тест обязан покраснеть → вернуть. Строка в CATALOG §F
6. Быстрый — удалить; постоянный — оставить и записать решение→факт в commit
```

**5 вопросов перед тестом** (что тестирую → зачем → сценарии/регрессии/edge → что ловилось → что зафиксирую)
— это **шаг мышления**, а не артефакт в коде. Ответы идут в **commit-сообщение** и `_sessions.md`.
Docstring теста — **одна строка**: что проверяет (+ `D#`/`F#`, если регрессия). Многострочные эссе,
история «прежде было X» и блоки «5 вопросов» в исходнике запрещены (директива владельца 2026-07-05).

## Жёсткие правила

- **Живой сервер** для поведенческих: `aiohttp` POST JSON-RPC 2.0 на `http://127.0.0.1:$MCP_SERVER_PORT/mcp`.
  Мок — только истинно внешние провайдеры (litellm/stable-ts), никогда как замена запуску сервера.
- **Изоляция:** тесты не зависят от порядка; состояние firewall сбрасывается между проверками.
- **Регрессия на каждый закрытый `D#`/`F#`** — в `test_audit_fixes` (единый дом), со ссылкой на номер.
- **Незавершённое — честно:** стаб обязан падать кодом реакции (G16); запланированное — `xfail(strict)`
  со ссылкой на `F#`, не «зелёный заглушкой».
