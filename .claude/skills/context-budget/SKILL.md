# Context Budget — что съедает окно

Окно контекста — **общий бюджет**, из которого до первого твоего хода уже вычтено то, что
подключено постоянно: описания инструментов MCP, описания скилов, цепочка `CLAUDE.md`,
`MEMORY.md`, вброс SessionStart-хука. Эта часть не видна в диалоге, но платится каждый ход.

Скилл отвечает на один вопрос: **сколько и на что уходит — по замеру, а не на глаз.**

Ось владельца «меньше своего кода» действует и здесь: строка, которая не тянет свой вес,
конкурирует с рабочим контекстом задачи.

---

## 1. Крупнейший потребитель почти всегда — MCP, а не скилы

Порядок величин, который стоит держать в голове до замера:

| Потребитель | Сколько стоит | Платится |
|---|---|---|
| Один инструмент MCP | ~300–800 токенов схемы | каждый ход, даже если инструмент ни разу не вызван |
| Сервер MCP на 25 инструментов | ~10–20k | каждый ход | <!-- снимок ок: прикидка порядка величин, не замер нашей базы -->
| `description` скила | ~40–120 токенов | каждый ход (тело `SKILL.md` — только при вызове) |
| Тело `SKILL.md` | 1–3k | только когда скилл вызван |
| `CLAUDE.md` (глобальный + проектный) | сумма файлов | каждый ход |
| `MEMORY.md` + подгруженные файлы памяти | сумма | старт сессии |
| Вброс SessionStart-хука | сумма вывода хука | старт сессии |

Отсюда главный вывод, который переживает любые числа: **скилы дёшевы, MCP дорог.**
Скилл платит описанием и раскрывается лениво; сервер MCP платит схемами всех своих
инструментов постоянно. Сокращать библиотеку скилов ради контекста — почти всегда не туда.

## 2. Замер (не оценка)

Числа в этом файле НЕ прописаны намеренно: они протухнут, а протухший факт хуже отсутствующего.
Считай в текущей сессии:

```bash
# 1. Скилы: сколько стоят описания (постоянно) и тела (лениво)
for f in ~/.claude/skills/*/SKILL.md; do
  d=$(sed -n '/^description:/,/^[a-z-]*:/p' "$f" | wc -w)
  printf "%-24s desc:%3sw  body:%5sw\n" "$(basename $(dirname $f))" "$d" "$(wc -w < $f)"
done | sort -k3 -rn

# 2. Цепочка CLAUDE.md + память
wc -w ~/.claude/CLAUDE.md ./CLAUDE.md 2>/dev/null
wc -w ~/.claude/projects/-home-admin-projects-video-pipeline-mcp/memory/*.md | tail -1

# 3. Вброс SessionStart-хука — то, что приезжает до первого хода
bash .claude/hooks/vpm-skill-bundle.sh </dev/null | wc -w

# 4. Серверы MCP: сколько их и какие
python3 -c "import json;d=json.load(open('.mcp.json'));print(len(d.get('mcpServers',{})), list(d.get('mcpServers',{})))" 2>/dev/null
```

Перевод в токены: проза ≈ `слова × 1.3`, код/JSON ≈ `символы / 4`. Точность до десятков
процентов достаточна — решение принимается по порядку величины, а не по третьей цифре.

Число инструментов MCP на глаз не считается: смотри системное сообщение сессии (в нём
перечислены подключённые инструменты) — оно и есть источник правды о том, что реально
приехало, а `.mcp.json` говорит лишь о том, что объявлено.

## 3. Три ведра для каждого потребителя

| Ведро | Признак | Действие |
|---|---|---|
| **Нужен всегда** | используется в большинстве сессий этого проекта | оставить |
| **Нужен иногда** | доменный, вызывается редко | подключать по требованию, не постоянно |
| **Не нужен** | ни одного вызова за проход; дублирует то, что есть локально | отключить |

Про MCP есть отдельный, самый доходный признак: **сервер оборачивает CLI, который у тебя и так
есть**. `git`, `docker`, `fetch`, файловые операции — всё это в этом проекте делается `Bash`,
`Read`, `Grep`, а обёртка MCP берёт за это десятки тысяч токенов каждый ход. Обёртка окупается,
только когда даёт то, чего в CLI нет.

## 4. Что делать с найденным

Порядок по доходности, а не по удобству:

1. **Отключить серверы MCP из ведра «не нужен»** — единственный шаг, дающий десятки тысяч.
2. **Ужать `description` скила**, если он раздут: описание платится всегда, тело — нет.
   Но не ценой триггера: размытое описание = скилл перестаёт подхватываться, и это дороже
   любой экономии (см. `skill-curator`).
3. **Ужать вброс SessionStart-хука** до адресов, а не содержимого: хук обязан говорить
   «таблица связок — в `engineering-questions`», а не печатать саму таблицу.
4. **Не тащить документ целиком, если нужен раздел.** `docs/roadmap/*.md` — крупные файлы;
   `grep -n` + чтение окна дешевле `Read` всего файла в разы.
5. **`CLAUDE.md` — конституция, не справочник.** Всё, что является содержанием, а не правилом,
   уезжает в скилл/память/`docs/roadmap`, а в `CLAUDE.md` остаётся ссылка.

## 5. Проверка, что правка окупилась

Экономия доказывается тем же способом, что и любая правка в этом проекте — **замером до и
после, в одном ходе** (`verified-edits`). «Отключил сервер, стало легче» — не доказательство;
доказательство — прежнее и новое число инструментов в системном сообщении новой сессии.

Признак, что оптимизация ушла не туда: сэкономил на скилах и памяти (сотни токенов), не тронув
MCP (десятки тысяч). Это перекладывание, а не экономия.

## Constraints

### MUST DO
- Считать запуском команд в этой сессии; числа в отчёте сопровождать способом их получения.
- Начинать разбор с MCP — там лежит основная масса.
- Сохранять точность `description` скила при любом ужатии (триггер дороже экономии).
- Доказывать экономию сравнением замеров до/после, а не ощущением.

### MUST NOT DO
- Приводить абсолютные числа из памяти или из этого файла как текущее состояние.
- Резать библиотеку скилов ради контекста (тело грузится лениво — экономии почти нет).
- Считать `.mcp.json` источником правды о том, что реально подключено в сессии.
- Превращать `CLAUDE.md` в справочник «чтобы было под рукой».
