# Project Conventions — video_pipeline_mcp

Слой **конформности при создании**: куда положить, как назвать, как оформить, чтобы новый артефакт неотличим от существующего. Отличие от `code-quality` (ревьюит уже написанное на архитектуру) — этот скилл про **структуру/размещение/стиль в момент создания** файла/модуля/инструмента/теста/конфига.

Источник правды по размещению/тестам — memory **`project-rules`** (матрица §2, тест-правила §3). Этот скилл его **не дублирует**, а активирует и добавляет **стиль**. Стек — **Python + Pydantic v2**, комментарии/доки — по-русски (как в проекте).

## Порядок работы (ОБЯЗАТЕЛЬНО перед созданием)

> Авторитет процесса — `the project workflow (memory project-workflow-canonical)`. Тип задачи — «новый код» / «новый функционал».

1. **Свериться с `project-rules` §2** (матрица размещения) ДО создания файла: две вселенные (код/конфиг в git-дереве; данные только в `workspace/`, НЕ git); `config/`=декларации, `core/`=логика, `tools/`=тонкие обёртки, `tests/`=только по структуре.

4. **После создания — запись:** решение→факт в commit + `docs/roadmap/_sessions.md` (формат ниже).

## Размещение (хаб — memory `project-rules` §2)

Не повторяю матрицу целиком — она в `project-rules`. Ключевые «жёсткие» правила:
- Данные — **только** `workspace/**`, никогда в дерево сервера (анти-паттерн: `_SESSION_LOG.md` в корне репо — известный footgun).
- Логика операции — в `core/`, НЕ в обёртке; обёртка тонкая (`tools/<группа>/__init__.py`). Слоя
  `config/ops/` в проекте **нет** (снят S22, каталог снесён S24 по `F83`) — не отправляй туда логику
  и не заводи его «как принято»: это отдельное решение, а не конвенция.
- `config/*.yaml` = декларации, не логика.
- Тест: быстрый → `tests/quick/` (создал→запустил→удалил, кроме регрессий `test_audit_fixes`/`test_tunnel`); постоянный → `tests/<name>/test_<name>.py` + `history.md`. Никогда вне `tests/` по структуре.
- **Скрипт: сначала реши, судит он или помогает.** Судит по УЛИКЕ (замер, храповик, сравнение двух
  источников, прогон) и падает exit-кодом → `scripts/guards/` И строка-зона в
  `scripts/guards/CATALOG.md`; без строки гейт красный (`guards_off_catalog`). Помогает владельцу
  (генератор схемы, установка модели, ключ провайдера) → уровнем выше, в `scripts/`, и в гейте не
  участвует.
- **Новый сторож и новый тест — последнее средство, а не первое.** Слепая зона НЕ повод заводить
  файл: у каждого сторожа и каждого набора объявлен ЗАПАС расширения, и ось почти всегда ложится в
  него строкой. Новый оправдан, только когда наблюдение вне зоны ВСЕХ существующих И запас
  естественного хозяина исчерпан (впитать сделало бы его разнородным). Причина жёсткая: разнородный
  сторож даёт ложные срабатывания, а врущего сторожа выключают целиком — вместе со всеми его
  настоящими проверками. Зоны: `scripts/guards/CATALOG.md` и `tests/CATALOG.md`.

Сверяйся с §2 перед КАЖДЫМ новым файлом. Детали стиля — `references/style-guide.md`.

### Студия (React/TS): тот же принцип, другой этаж

Фронтенд-кода в проекте пока НЕТ ни одного файла — раздел вступает в силу с ПЕРВОГО `.tsx`.
Каталог объявлен решением `20` §0 п. 4 («тот же репозиторий, отдельный каталог»), но ИМЕНИ ему не
давали: не выдумывай его молча — спроси или сошлись на решение.

| Что | КЛАСТЬ | НЕЛЬЗЯ |
|---|---|---|
| Примитив (кнопка, карточка, поле) | слой примитивов: **один на роль**, назначения различают варианты | не пятый похожий компонент рядом с экраном (`20` §4а) |
| Токен: размер, отступ, шрифт, цвет | один объявленный источник токенов | не значение внутри компонента — это `anti-hardcode` |
| Экран / фича | по тому же Bounded Context, что и `tools/`: продакшен (ниши→сетки→каналы→видео, конкуренты) и редактор (сцены, слои, таймлайн, звук) | не общий `components/` свалкой без контекста |
| Обращение к серверу | ОДИН клиентский слой MCP-вызовов | компонент не ходит в сеть сам: дверь записи одна (`20` §0 п. 1) |
| Данные | их здесь нет вовсе — студия читает через сервер | никакой копии `workspace/` в дереве студии: правило двух вселенных не отменено |

**Граница ответственности файла — то же правило, что «обёртка тонкая».** Компонент, который И тянет
данные, И решает раскладку, И рисует, — толстая обёртка: данные тянет слой доступа, раскладку задаёт
экран, рисует примитив. Признак нарушения тот же, что на сервере: чтобы поменять одно, приходится
читать всё.

## Карта системы: где ответ лежит (чтобы не гадать и не грепать вслепую)

Список собран из вопросов, на которые сессии тратили ходы заново. Проверять — командой, а не памятью:
цифры устаревают, адреса — нет.

| Вопрос | Где ответ / чем узнать |
|---|---|
| Сколько инструментов и как они объявлены | эталон `tests/quick/tools_inventory.golden.json`; объявление — `engine.register(name=…, handler=…, group=…)` в `tools/<группа>/__init__.py`, обёртка тонкая |
| Схема параметров инструмента | тот же golden: `python -c "import json;d=json.load(open('tests/quick/tools_inventory.golden.json'));print(d['<имя>']['input_schema'])"` |
| Какие коды отказов существуют | `config/server_reactions.yaml` (ключ верхнего уровня = код; `DEFAULT` — фолбэк). Новый код заводится ТАМ, не строкой в коде |
| Что советует сервер на успехе | `config/recommendations.yaml` + `ctx.advice.get("<ключ>", **контекст)` — второй канал рядом с реакциями (F59) |
| Как отказ файрвола виден клиенту | НЕ кодом реакции: транспорт отвечает HTTP **403** (BLOCK) и **429** (RATE_LIMIT) — `server.py`, обработчик `/mcp`. Ассертить в тестах по статусу |
| Где в ответе MCP что лежит | `content[0].text` — данные; `structuredContent` — `facts` на успехе и `code`/`reaction_class`/`recovery` на отказе; роль `status` играет родное `isError` |
| Как поднять живой сервер под тест | `with live_server() as srv:` (`tests/harness`) — свой порт, своя временная область (`MCP_WORKSPACE`), настоящий ключ; готовность по ОТВЕТУ на `tools/list` |
| Как устроены наборы тестов | самостоятельные скрипты со своим счётчиком и `sys.exit`; гоняет их `tests/test_suites.py` подпроцессом (exit-код = вердикт), новый файл `tests/**/test_*.py` попадает в гейт сам |
| Кто знает иерархию сущностей | `core/ids/taxonomy.py` — читает `id:`/`children:` из `config/templates/workspace/*.tpl.yaml`. Хардкода таксономии в поиске больше нет |
| Где заводится новый тип факта | `KNOWN_FACT_TYPES` в `core/contracts/fact.py`. Не внёс — тесты падают по `UserWarning` (D25), а не молча |
| Сколько чего в реестре находок/планах | ПЕРЕСЧИТАТЬ скриптом по строкам самого документа. Число из шапки не наследовать: так шапка `02_findings.md` и разошлась сама с собой (говорила «24 открытых» при 26 в перечне) |

**Две вещи про дерево сущностей, на которых легко построить неверный обход:**
- **Уровень иерархии разрешено ПРОПУСКАТЬ** — канал прямо под нишей, без сетки (`skipped_levels` в ответе
  создания). Любой обход, спускающийся только по ПРЯМЫМ детям типа, потеряет такую ветку целиком.
  Спускаться надо по всем потомкам, для которых этот тип объявлен предком (`Taxonomy.descendant_containers`).
- **Контейнер может нести токен `{parent:<тип>}`** (`competitors/{parent:channel}/`), который либо подставлен
  именем предка, либо ОПУЩЕН, когда предок неизвестен (§4). Поэтому сравнивать имя каталога с объявлением
  буквально нельзя: `"competitors" == "competitors/{parent:channel}"` ложно, и ветка становится невидимой
  (`F93`). Разбирать оба варианта, а сегмент, совпавший с именем предка-якоря, считать группировкой,
  а не сущностью.
| Что где лежит в рабочей области | `workspace/` под `MCP_WORKSPACE`; реестр сущностей — `_id_registry.json`; закрытые каталоги (`.secrets`) — единая дверь `core/secrets.py` |
| Границы записи | `core/paths.safe_resolve` (containment, G17) + `core/write_policy.py` со списком типов из `config/firewall.yaml → write_allowlist` |
| Где журнал и точка возобновления | `docs/roadmap/18_full_pass.md` (журнал сплошного прохода) и `_sessions.md → RESUME`; реестр находок — `02_findings.md` |

## Стиль (то, чего нет в `project-rules` — детали в `references/style-guide.md`)

1. **Module-header docstring — КОРОТКИЙ, и это проверяет хук, а не вкус.** Лимиты, на которых он ругается
   при сохранении: шапка модуля **≤15 строк**, **≤2** раздела `##` в одном докстринге, докстринг функции
   **≤12 строк**; отдельно ловится история («прежде было», «(было: …)») в комментариях и ассертах.
   Знай их ДО правки: подгонять шапку по одной строке за проход — потерянные ходы. Формат, который
   проходит: одна строка роли + `## Назначение` (2–3 строки) + `## Границы` (список неочевидного).
   НЕ раздувать блоками «## 4 уровня анализа / ## Поток данных / ## Порядок полей» — это process-нарратив,
   а не навигация по коду (владелец 2026-07-05). «4 уровня» — шаг мышления ([[engineering-questions]]),
   не артефакт в файле. Правишь файл — заодно пропалываешь его легаси-шапку: хук всё равно укажет на неё.
   **Проверяет не только хук, а гейт** (S24): правило живёт в `scripts/guards/comment_guard.py` (хук
   `.claude/hooks/vpm-comment-guard.py` — шим сюда, копии правила нет), джоба CI `comment-guard`
   гоняет `--check` — пофайловый храповик против `scripts/guards/comment_guard_baseline.txt`. Новый файл
   идёт в замер с потолком **0**: длинная шапка в нём краснит гейт сразу, а не «когда-нибудь на
   прополке». Прополол — опусти потолок: `python3 scripts/guards/comment_guard.py --bless`.
   Свой замер до правки: `python3 scripts/guards/comment_guard.py --scan <путь>`.
   **Слепые пятна сторожа, перечисленные здесь раньше, ЗАКРЫТЫ** (перепроверено прогоном 2026-08-21,
   `F122`–`F126`): цели он берёт из `git ls-files`, поэтому новый пакет попадает в замер сам; границы
   текста даёт `ast`+`tokenize`, поэтому строка-данных его больше не сбивает и решётка внутри неё не
   считается комментарием; пересказ декларации ловит `DECL_LINE` (предел 3 строки «ключ: значение»).
   **Но молчание сторожа всё равно не аттестат чистоты:** пересказ соседнего YAML СВЯЗНОЙ прозой,
   без двоеточий, не ловится ничем, кроме длины и ревьюера. Читай шапку глазами.
   Не верь этому абзацу на слово — прогони синтетику: правило скила устаревает быстрее кода.
2. **Naming** — `fs_*`/`table_*`/`excel_*`/`structure_*`/`search_*` для инструментов по Bounded Context; snake_case модулей; `test_<что>.py`.
3. **Комментарии — терсовые, про КОД:** одна строка «почему» для неочевидного поведения (`# word-boundary: "act as narrator" — легит доменный текст`). **ЗАПРЕЩЕНО в коде/тестах:** многострочные `D#`-эссе, история «прежде было X», блоки «5 вопросов: Что/Почему/Сценарий/…», аудит-нарратив. Это process-метаданные → в commit + `docs/roadmap/_sessions.md`, НЕ в исходник (владелец 2026-07-05: «таски в код» = зараза). **Координата задачи запрещена ЦЕЛИКОМ** (владелец 2026-08-21, прежнее послабление «короткий тег с реальным почему» отменено): ни меток находок, ни сессий прохода, ни фаз плана, ни номеров мутаций — ни в комментарии, ни в докстринге, ни в шапке модуля, ни в комментариях `config/*.yaml`/`ci.yml`/`pyproject.toml`. Пиши сразу «почему» без указателя: реестр находок заморожен, так что указатель ведёт в никуда. Исключения ровно два: имя проверки в ассерте (`check("D1 traversal blocked", …)` — по нему `tests/CATALOG.md` связывает находку с тестом) и имя правила чужого линтера (`ruff D301`). Ловится сторожем `scripts/guards/comment_guard.py` — в `PostToolUse`, в `pre-commit` и в CI.
4. **Контракты:** инструмент всегда возвращает `ToolResult`; ошибка — `ErrorDetail` внутри; факты — `Fact` из `KNOWN_FACT_TYPES`; статусы/коды — `Literal`/реестр (не магические строки — стык `code-quality` G15).
5. **Запись решение→факт (commit-сообщение):** версия `X.Y — дата — заголовок`, блок **Решение** (мотив/рефактор/проверено) → затем **Факт**. Сначала решение, потом факт (правило `workflow.md`). По-русски.
6. **Pydantic v2 на сервере**, без TS/Zod в его дереве; TypeScript живёт только в каталоге студии. Комментарии/доки по-русски, код-идентификаторы по-английски — на обоих этажах.
7. **Студия (React/TS):** имя файла = имя компонента (`PascalCase.tsx`), **один компонент — один файл — одна роль**; хук `useЧто.ts` лежит при своей фиче, а не в общей куче «hooks/». Комментарии — по п. 3 без послаблений: терсово, про код, координат задачи нет. Разница в принуждении: `.tsx` сторожем пока не покрыт (условие — первый компонент, `20` §4), поэтому правило держится ревью, а не гейтом, — и потому строже, а не свободнее. **Каждый примитив отдаёт стабильный `data-component`** (`20` §4б): без него на вопрос «какой компонент это рисует» не ответить ни по скриншоту, ни по DOM.

## Имена ключей в объявлениях: `on`, `yes`, `no`, `off` — не имена

YAML читает их как булевы, и ключ пропадает молча: `on:` в роутере карты пришёл в разбор как `True`,
и объявление «потеряло» поле без единой ошибки. Называй `by`, `enabled`, `mode`. Проверка одна:
`python3 -c "import yaml,sys; print(yaml.safe_load(open(sys.argv[1])))" файл.yaml` — если ключ в
выводе стал `True`, имя выбрано неверно.

## Core Workflow

1. **Locate** — что создаю; по матрице §2 определить директорию; проверить антидубль.
2. **Shape** — имя по конвенции; module-header (если модуль ядра); контракт на выходе.
3. **Match style** — открыть соседний файл того же типа, повторить идиомы/плотность комментариев/шапку.
4. **Record** — решение→факт в commit + `docs/roadmap/_sessions.md`; новый файл-тест → `history.md` набора.

## Constraints

### MUST DO
- Сверяться с `project-rules` §2 перед созданием файла; проверять антидубль.
- Данные только в `workspace/`; логика в `core/`, обёртка тонкая; тест по структуре.
- Оформлять module-header (ядро) и контракт `ToolResult`; привязку к `D#`/`G#` писать в commit, не в файл.
- Копировать идиомы соседнего файла (код читается как существующий).
- Запись решение→факт в commit + `docs/roadmap/_sessions.md` после создания.

### MUST NOT DO
- Класть данные в дерево сервера / код в `workspace/` / логику в обёртку / тест вне `tests/`.
- Дублировать матрицу размещения в теле кода — она в `project-rules`.
- Плодить новый файл/инструмент там, где хватило бы расширения.
- Магические строки статусов/кодов вместо `Literal`/реестра (→ `code-quality`/`anti-hardcode`).
- Ссылаться на канон-док, не проверив, что он существует на диске.
