# Стиль-гайд video_pipeline_mcp — детали

> Разворачивает раздел «Стиль» из `SKILL.md`. Эталоны сняты с реального кода проекта (`core/firewall/*`, `core/contracts/*`, `core/providers/*`).

---

## 1. Module-header docstring — КОРОТКИЙ (1–3 строки)

Только путь + роль модуля. Пример:

```python
"""core/<module>/<file>.py — <роль: что делает и для чего, 1–2 строки>."""
```

❌ **НЕ раздувать** блоками `## 4 уровня анализа` / `## Поток данных` / `## Порядок полей` — это process-нарратив, а не навигация по коду (владелец 2026-07-05: «таски в код» = зараза). «4 уровня анализа» — приём **мышления перед работой** ([[engineering-questions]]), его место — в голове/commit, не в шапке файла. Легаси-файлы с раздутыми шапками пропалывай при первой правке.

## 2. Naming

- **Инструменты** — `<context>_<action>`: `fs_read_file`, `table_get_row`, `excel_add_sheet`, `structure_create`, `search_tables`. Контекст = Bounded Context.  <!-- снимок ок: примеры формы имени, не опись инструментов -->
- **Модули** — snake_case, по контексту: `core/firewall/rules/rate_limiter.py`.
- **Тесты** — `test_<что>.py`; наборы — `tests/<name>/test_<name>.py`.
- **Контракты/классы** — CamelCase: `ToolResult`, `ErrorDetail`, `FirewallRequest`.  <!-- снимок ок: примеры формы имени класса -->
- **Реестры-данные вместо веток** — `TYPE_PREFIX`, `ROOT_CONTAINER`, `DEFAULT_DANGEROUS_TOOLS` (словари, не цепочки `if` — стык `anti-hardcode`).

## 3. Комментарии — терсовые, про КОД (не про историю/процесс)

Одна строка «почему» для неочевидного поведения — про сам код:
```python
# бан НЕ с первого превышения: за туннелем Claude под одним IP, всплеск ≠ атака
```
❌ **Запрещено в коде/тестах** (это «таски в код», зараза — владелец 2026-07-05):
```python
# D33/D34/D35: ... 5 вопросов: Что — ... Почему — ... Сценарий — ... Ловилось — ... Фиксирую — ...
# прежняя логика делала X, потому что Y, но по шаблонам Z ...   ← история в код
```
Многострочные `D#`-эссе, «5 вопросов», «прежде было X», аудит-нарратив → в commit + `docs/roadmap/_sessions.md`-сообщение. Короткий `D#`-тег допустим, только если несёт реальное «почему» одной строкой. Комментарий, повторяющий код (`# increment i`), — шум, удаляй.

## 4. Контракты на выходе

- Всегда `ToolResult(status, data?, error?, facts?)`. Ошибка — `ErrorDetail(code, message, recovery?)` внутри, не `raise` наружу.
- `code` — из `KNOWN_ERROR_CODES` + `config/server_reactions.yaml` (D4: синхронить оба). Новый код → добавить в оба.
- `Fact(type=...)` — `type` из `KNOWN_FACT_TYPES` (D25: синхронить). Новый факт → добавить в реестр.
- Статусы — `Literal[...]` (эталон `TaskStatus.status`), не свободные строки.

## 5. Запись решение→факт (формат commit-сообщения)

```markdown
## vX.Y — YYYY-MM-DD — <заголовок>

### Решение
- **Мотив:** <зачем>
- **Рефактор/что сделал:** <как>
- **Проверено:** <юнит/эмпирика>
- **Правило:** <вывод на будущее>

### Факт
<что теперь по факту в коде>
```
Сначала **Решение**, потом **Факт** (канон — память `project-workflow-canonical`). Обновить `> Последнее обновление:` в шапке файла. По-русски.

## 6. Язык и стек

- Комментарии, docstring, история — **по-русски**. Идентификаторы кода — по-английски.
- **Python + Pydantic v2** только. Нет TS/Zod/npx/Jest.
- Атомарная запись данных — через temp+rename (эталон `_atomic_write_json`), не прямая.
