# npm — поставка для студии

Те же три вопроса, что у pip (манифест ↔ лок ↔ установленное; можно ли доверять; поддерживаем ли),
на другой экосистеме. Разница, из-за которой нельзя переносить привычки pip дословно: транзитивных
пакетов на порядок больше, а скрипты установки исполняются на машине сборки — в CI рядом с его
секретами.

Оглавление: деревья · три источника · прежде чем добавить · скрипты установки · свежие версии ·
advisory · что не делать.

## Деревья

У студии и у эмуляции студии — свой `package.json` и свой `package-lock.json`, оба под git, оба
ставятся `npm ci` в своих джобах `ci.yml`. Правка манифеста одного дерева другое не трогает, и
доказывается в своём дереве.

## Три источника

- **Лок — правда, манифест — намерение.** В CI и в настройке среды только `npm ci`: он падает, если
  манифест и лок разошлись, и никогда не переписывает лок. `npm install` в CI молча чинит
  расхождение — и скрывает его.
- Правка манифеста без обновлённого лока в том же коммите — дефект того же класса, что манифест ↔
  `.venv` у pip.
- Версия Node в CI и `engines.node` манифеста совпадают; «у меня работает» на другой мажорной версии
  Node — не улика.

## Прежде чем добавить пакет

1. **Нужен ли он.** Платформа уже умеет многое: `Intl.*` для чисел и дат, `structuredClone`,
   встроенные методы массивов в пределах пола браузеров (`studio-web-standards`). Пакет ради одной
   функции — вес бандла и ещё одна поверхность атаки.
2. **Существует ли он на самом деле.** Имя, предложенное ИИ, проверяется в реестре ДО установки:
   выдуманные имена регистрируют злоумышленники (slopsquatting).
   ```bash
   npm view <пакет> name version license repository.url maintainers time.created time.modified
   ```
   Свежесозданный пакет с похожим на известное именем, без репозитория или с одним сопровождающим
   без истории — стоп.
3. **Лицензия.** MIT, Apache-2.0, BSD, ISC — можно; без лицензии — нельзя вовсе (так отклонён
   пакет анимаций в плане студии §4б), копилефт — решение владельца.
4. **Условие владельца:** ни одной зависимости, которой нужен API-ключ или которая шлёт данные
   третьему лицу (план студии §4а).
5. **Вес.** Для одностраничного приложения всё, что импортируется в код, едет в бандл, в каком бы
   разделе манифеста пакет ни лежал. Вес после добавления видно по выводу сборки
   (`studio-web-standards`, бюджет бандла).
6. **Раздел.** Инструменты сборки и проверки — `devDependencies`; это разделение про установку, а не
   про безопасность: скрипты установки из `devDependencies` исполняются на CI точно так же.

## Скрипты установки

`preinstall`/`install`/`postinstall` исполняются при `npm ci` с правами сборки. Так распространялись
самораспространяющиеся черви по npm в 2025 году: украденный токен сопровождающего → новая версия
популярного пакета со скриптом, который читает секреты CI. Проверка перед добавлением и после
обновления лока — у каких пакетов дерева есть скрипты установки:

```bash
npm --prefix studio query ":attr(scripts, [postinstall])"
```

Пакет, которому скрипт установки не нужен по существу (не собирает нативный модуль), но который
его имеет, — вопрос. Жёсткий вариант — `ignore-scripts=true` в `.npmrc` дерева с явным списком
исключений; вводится решением, потому что ломает пакеты с нативной сборкой.

## Свежие версии

Компрометированная версия обычно живёт часы или дни, пока её не снимут. Поэтому обновление на
версию младше нескольких дней не принимается без причины: у `npm install` есть `--before=<дата>`,
которым дерево ставится так, как оно выглядело на дату. Подписи и происхождение пакетов реестра:

```bash
npm --prefix studio audit signatures
```

## Advisory

- `npm audit --omit=dev` — уязвимости того, что едет пользователю; полный `npm audit` — всего,
  включая сборку. Находка в dev-пакете не безвредна: он исполняется на CI.
- Реакция та же, что у pip (раздел «Реакция на advisory»): версия с исправлением, а если её нет —
  `overrides` в манифесте с причиной рядом и условием снятия. `overrides` без причины — второй
  источник правды о версии, который переживёт исправление апстрима.
- `npm audit fix --force` не запускается: он поднимает мажорные версии молча.

## Что не делать

- Не ставить глобальные пакеты ради проекта — всё, что нужно сборке, в `devDependencies` и в локе.
- Не подключать скрипты с CDN в `index.html` — это зависимость мимо лока и внешний получатель
  (`security-reviewer`, «Своя страница студии»).
- Не править лок руками — только `npm install <пакет>@<версия>` и коммит обоих файлов.
