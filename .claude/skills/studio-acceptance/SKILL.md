# Приёмка правки студии — по доменам

Правку в React ИИ ломает не там, где правит: переименованный пропс роняет соседний экран, «подровнял
отступ» меняет стиль приложения, переписанный `className` молча уносит анимацию. Найти такое трудно
не только человеку — в чужой код ИИ входит почти вслепую, и каждая следующая правка опирается на
предыдущую ошибку. Приёмка — это карта того, что обязано остаться верным, и КОМАНДА, которой это
доказывается. Слова «проверил глазами» приёмкой не считаются.

Скил судит, приемлема ли правка. Не учит, как выглядеть (`frontend-design`), и не доказывает, что
правка легла (`verified-edits`).

## Три слоя: каждая правка проходит все три

| Слой | Вопрос | Кто судит |
|---|---|---|
| **1. Правка ИИ** (П1–П12) | не сломал, не сменил, не вышел за задачу, адресуемо, имена и место честные | `acceptance_studio.py --суд` + `tsc`/`eslint`/сборка + геометрия в браузере |
| **2. Домен** | правка верна для ЭТОГО контекста: какие данные, какой жест, какое состояние экрана | предметы `студия-*` в `scripts/guards/acceptance_subjects.yaml`; пока механизма нет — ручная проверка по `references/domains.md` |
| **3. Платформа** | быстро, на любой ширине, в матрице браузеров, с клавиатуры и скринридером, без внешних получателей | `studio-web-standards`; разметка из недоверенных данных — `security-reviewer` |

Состояние каждого условия (судится / совет / нет) здесь не пишется — оно меняется без правки скила.
Карту печатает машина:

```bash
.venv/bin/python scripts/guards/invariants.py --приёмка
```

Условие слоя 1 почти всегда «общее для любого экрана», слоя 2 — «верно только здесь». Путать их
дорого: доменное условие, записанное как общее, превращается в правило «всегда так», которое
ломает соседний домен (у конкурента записи нет, у своего канала есть).

## Порядок работы (узкий мост — шаги не переставлять)

1. **Назвать домен и компонент ДО правки.** По скриншоту — атрибут `data-component` в DOM, по
   описанию — имя. Команда отдаёт файл, строку, пропсы и токены:
   ```bash
   .venv/bin/python scripts/guards/acceptance_studio.py --дерево studio/app --кто Panel
   ```
   Не нашлось — это находка П4 (маркера нет), а не повод искать «похожий» файл глазами.
2. **Суд ДО правки обязан быть чистым.** Грязный старт смешивает чужие нарушения с твоими, и
   приёмка перестаёт отвечать, что сломала именно эта правка. Грязно — сначала отделить старое
   (отдельным шагом или остатком), потом работать.
3. **Объявить зону задачи** — glob от корня репозитория. Без неё П3а (вышел за рамки) не судится,
   и сторож так и говорит; это не «чисто».
4. Правка.
5. **Суд после правки** — все три слоя:
   ```bash
   .venv/bin/python scripts/guards/acceptance_studio.py --суд --дерево studio/app --зона 'studio/app/screens/*'
   npm --prefix studio run typecheck
   npm --prefix studio run lint
   npm --prefix studio run build
   npm --prefix tests/studio_emulation run geometry
   ```
   Геометрия сегодня гоняется по дереву эмуляции; для экрана студии — тот же приём, см.
   `studio-web-standards` (матрица ширин и браузеров).
6. **Домен:** пройти условия своего домена из `references/domains.md` — каждое наблюдаемо (что
   увидел человек, что ушло на сервер), а не «код выглядит правильно».
7. **`--bless` только когда смена формы И ЕСТЬ задача** — и в том же коммите, что правка, с
   причиной в сообщении. Снимок «чтобы позеленело» стирает улику П2/П8 навсегда: снимок и есть
   единственный бэкап стиля.

Стиль или анимация пропали — вернуть ДОСЛОВНО, а не «похоже»:

```bash
.venv/bin/python scripts/guards/acceptance_studio.py --дерево studio/app --восстановить Panel
```

Предел, который надо помнить: П8 не видит переходов, записанных КЛАССАМИ Tailwind
(`transition-*`, `duration-*`, `animate-*`, `hover:-translate-*`) — остаток `7fec`. Пока он
открыт, эти классы в диффе сверяются построчно: исчезнувший класс анимации — такая же потеря, как
исчезнувший `@keyframes`.

## Отказы ИИ, ради которых приёмка существует

| Отказ | Почему ИИ так делает | Что ловит |
|---|---|---|
| переименовал компонент или экспорт | видит файл, не видит импортёров | П1: импорт ↔ экспорт цели |
| «подровнял» отступ, цвет, шрифт рядом с задачей | стремится к «аккуратному», не зная, что это решение | П2: литерал мимо токена, форма ↔ снимок |
| переписал `className` и потерял переход | собирает строку классов заново, а не правит | П8 (+ сверка классов, пока `7fec` открыт) |
| пропс «на будущее», обёртка ради обёртки | генерирует «полное» API | П3б: проп ↔ читатель, компонент ↔ отрисовщик |
| правка логики задела иконки и меню | переформатировал файл целиком | П3а: тронутое ↔ зона задачи |
| сетевой вызов в экране | «ближе к месту использования» | П5: род `сетевой-вызов` законен только в `mcp` |
| файл `utils.ts`, `helpers.tsx` | нет места — создал «общее» | П7: словарь пустых имён в `studio/structure.yaml` |
| текст вылез, карточки наложились на узком экране | проверял на одной ширине | П10 + матрица ширин (`studio-web-standards`) |
| копия пропса в `useState` + `useEffect` | шаблон «синхронизировать» | `no-unnecessary-effects` |
| «что-то пошло не так» вместо кода реакции | не знает контракта отказа | домен: `студия-общее` |
| успех показан до ответа сервера, отката нет | оптимистичный UI по шаблону | домен: `студия-общее` |
| счётчик хранится рядом со списком, который считает | переносит форму данных дизайна как есть | домен: производное — из одного источника |

## Перенос экрана из дизайна владельца

Дизайн — ориентир, а не исходник (решение владельца: не копировать, а проводить через сторожей).

1. **Замер дизайна до работы** — тот же сторож по распакованному дереву дизайна; число нарушений и
   есть объём переноса, а не впечатление «почти готово».
2. **Один экран за шаг**, до зелёного суда (решение 15 плана студии).
3. **Что снимается с дизайна всегда:** ключ API в сборке (`define: process.env.*`) · внешние
   картинки и шрифты по чужим адресам · сырая палитра Tailwind и `[#hex]` · `outline-none` без
   `focus-visible:` · `div` с `onClick` · модалка без роли диалога, `Escape` и возврата фокуса ·
   посевные данные в экране. Посев живёт только за дверью `studio/app/mcp/` честным стабом.
4. **Числа приходят числами.** В дизайне подписчики и просмотры — строки («142.5K»): такая строка не
   сортируется, не сравнивается и не локализуется. Формат — одна функция отображения, а не данные.
5. **Словари статусов — из объявления сервера**, а не из дизайна: там несколько разных словарей
   одного жизненного цикла, и род слова в них разный («принят» / «принято»).

## Как объявить новое доменное условие

Условие, живущее только прозой, — пожелание. Оно объявляется в `acceptance_subjects.yaml`:

```yaml
  студия-<домен>:
    про: что это за контекст и какие данные он показывает
    условия:
      <Ид>:
        про: что обязано быть верным — одной фразой и НАБЛЮДАЕМО
        механизм: парная улика — X ↔ Y, а не счёт литералов
        состояние: нет
        ждёт: какой механизм, где встанет и что для него нужно
        улика: команда, которой видно положение дел сегодня
```

- **Наблюдаемо** — что увидел человек или что ушло на сервер. «Компонент использует хук» —
  реализация, не условие (`test-master`, анти-паттерн «проверка реализации»).
- **Парная улика** — две стороны, обязанные совпадать (жест ↔ число вызовов записи, версия
  прочитанной строки ↔ ответ сервера). Одна сторона без пары судит вид, а не правду.
- **«нет» честно, с `ждёт`.** В «судится» условие переходит только с механизмом, у которого ОБЕ
  стороны в наборе: ловит нарушение и молчит на чистом (`test-master`).
- Долг «условие без механизма» — храповик: рост потолка только `--bless --почему`.

## Границы

- `frontend-design` — как выглядит и почему именно так; здесь — не сломалось ли то, что выглядит.
- `verified-edits` §3а — правка легла и доказана разбором; здесь — правка приемлема по условиям.
- `studio-web-standards` — платформа: скорость, ширины, браузеры, доступность.
- `security-reviewer` — недоверенные данные в разметке, ключи, внешние получатели.
- `project-conventions` — куда класть файл и как его назвать (`studio/structure.yaml`).
- `test-master` — каким тестом условие переходит из «нет» в «судится».
- `no-unnecessary-effects` — нужен ли эффект вообще.
