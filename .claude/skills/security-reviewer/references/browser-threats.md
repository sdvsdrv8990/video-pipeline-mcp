# Браузерный класс угроз — что проверено, чем, когда

Клиент сервера — **Claude AI Web**: он ходит к нам через браузер, поэтому браузер в цепочке
доверия по построению. Отсутствие собственного веб-UI убирает ровно одну угрозу — XSS в НАШЕЙ
разметке; всё остальное (CORS, CSRF, confused deputy, rebinding, sniffing, clickjacking через
встраивание) остаётся, потому что для них нужна ЧУЖАЯ страница, а не наша.

**Правило записи.** Строка «нам это не грозит» допустима только с (а) конкретным запросом,
которым это проверено, (б) наблюдённым ответом, (в) датой. Без них она работает выключателем
проверки ДО её начала — так проект и пропустил `F103` (нашёл сторонний conformance-прогон).

## Разбор класса (проверено на живом сервере, S24 · 2026-08-16/17)

| Угроза | Чем проверено | Что было | Что стало |
|---|---|---|---|
| CORS / preflight | `OPTIONS /mcp` + `Access-Control-Request-Method/Headers`, `Origin: https://evil…` | `405`, ни одного `Access-Control-*` — preflight проваливается, браузер не даёт странице ни послать ключ, ни прочитать ответ | так же, плюс регрессия: появление любого `Access-Control-*` красит гейт |
| `Origin` | `POST /mcp` с валидным ключом и `Origin: https://evil.example.com` | **200** — `Origin` валидировался только при непустом `MCP_ALLOWED_ORIGINS`, то есть по умолчанию никогда (`D12`) | `403 Forbidden origin` (`F106`); петлевой `Origin` принимается — того требует спека, а подделать его удалённый сайт не может |
| CSRF без preflight | `POST` с `Content-Type: text/plain;charset=UTF-8` (простой запрос: preflight не нужен) | при открытой калитке `MCP_ALLOW_NO_AUTH` **файл реально создан** в рабочей области | `415` до разбора тела (`F107`) — и три «простых» типа (`text/plain`, `x-www-form-urlencoded`, `multipart/form-data`) отбиты по построению |
| SSE / streamable HTTP | `GET /mcp`, `Accept: text/event-stream` | `405`, поток не открывается — спека транспорта это разрешает явно | так же; регрессия заставит заново пройти браузерный разбор, если GET-поток появится |
| Идентификатор сессии | `initialize`, затем `Mcp-Session-Id: stolen` без ключа | сессий сервер не выдаёт вовсе; чужой идентификатор → `401` | так же, закреплено ассертом: **владение хэндлом ≠ аутентификация** |
| `credentials: include` | запрос с `Cookie:` без ключа | `401`; `Set-Cookie` сервер не ставит никогда — прикладывать к запросу нечего | так же, закреплено |
| Заголовки ответа | любой ответ | ни `nosniff`, ни CSP, ни `no-store`; `Server: Python/3.14 aiohttp/3.14.3` объявлял точную версию | `F109`: `nosniff` · `default-src 'none'; frame-ancestors 'none'` · `no-referrer` · `no-store` · `Server: mcp` |
| Разбор `Host` | `Host: 127.0.0.1:8080, evil.com` | **200** — разбор брал первое значение до запятой | `403` (`F108`): запятая = склейка двух заголовков посредником, выбор значения нельзя отдавать отправителю |

## Что из этого — механизм, а что рассуждение

- **Работает по построению:** `Content-Type: application/json` браузер кросс-доменно поставить
  без preflight не может, а preflight мы не одобряем. Это единственный слой, который держит,
  даже если auth выключена калиткой.
- **Работает, пока никто не добавил CORS:** любой `Access-Control-Allow-Origin` в ответе мгновенно
  превращает `fs_*` в публичный API для всех сайтов. Поэтому «добавить CORS, чтобы заработало»
  — не решение проблемы, а её создание; регрессия обязана краснеть на такое.
- **Петлевой `Origin` принимаем осознанно:** DNS-rebinding оставляет в `Origin` имя атакующего
  (`http://evil.com`), потому что браузер ставит его по адресу самой страницы. Петлю подделать
  может только уже локальный злоумышленник — это другой класс.

## Эталоны, откуда взяты механизмы

- Спека транспорта MCP (`2025-06-18`): «Servers **MUST** validate the `Origin` header on all
  incoming connections», «bind only to localhost», «implement proper authentication». Ответ `405`
  на `GET` вместо SSE-потока разрешён явно.
- Сценарий `dns-rebinding-protection` из `@modelcontextprotocol/conformance`: требует **обе**
  стороны — чужой `Host`/`Origin` отбить (4xx) И петлевой принять (2xx). Проверка «только
  отбить» проходит наполовину и делает набор красным.
- `modelcontextprotocol/typescript-sdk`, `packages/server/src/server/streamableHttp.ts`:
  `validateRequestHeaders` (Origin: `if (origin && !allowed.includes(origin)) → 403`) и
  `isJsonContentType` → `415`. Оттуда же правило разбора: **сравнивать разобранный media type,
  а не искать подстроку** — `text/plain; a=application/json` содержит подстроку `application/json`,
  но его тип `text/plain`. У нас разбор берёт `aiohttp` (`request.content_type`), в коде остаётся
  только политика — и он же безопасно отдаёт `application/octet-stream` на склеенный
  `application/json, text/plain`.

## Чего НЕ делать (проверено, стоило бы дороже)

- Не «чинить» упавший браузерный клиент добавлением CORS-заголовков — сначала выяснить, кто и
  откуда ходит: наш штатный клиент `Origin` не шлёт вовсе.
- Не требовать `Accept: application/json, text/event-stream` (спека требует от КЛИЕНТА): это
  конформанс, не защита, а ломает обычные инструменты вроде `curl`/`httpx`.
- Не заводить свою сессию ради «привязки вкладки»: серверная сессия не аутентифицирует
  (нормативно), а даёт новый угоняемый идентификатор.
