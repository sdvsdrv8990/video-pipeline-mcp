# Банк инженерных вопросов по типам задач

> Углубляет общий блок из `SKILL.md`. Для каждого типа — вопросы по осям. 🔴 = красный (без ответа не кодим). Отвечай коротко и письменно; ключевые ответы → docstring/`history_*.md`.

---

## A. Новый инструмент / функционал

**Границы и дизайн**
- 🔴 Какой Bounded Context (`filesystem`/`tables`/`excel`/`structure`/`search`/`media`)? Инструмент не лезет в чужой?
- 🔴 Антидубль: нет ли уже такого инструмента/операции? Расширить существующее вместо нового?
- Логика в `core/` (или задокументированный inline — `config/ops/` в проекте нет, `F83`)? Обёртка тонкая?
- Имя по конвенции `<context>_<action>`? Куда файл по `project-rules` §2?

**Контракт**
- 🔴 Возвращает `ToolResult`? Ошибка — `ErrorDetail` внутри, не `raise`/сырой текст?
- Новые коды реакций → в `KNOWN_ERROR_CODES` + `server_reactions.yaml` (D4)? Новые факты → `KNOWN_FACT_TYPES` (D25)?
- `input_schema` валидирует вход ДО исполнения (D5)?
- Parity: `facts`/`status` доедут до клиента в MCP `content`, не потеряются на границе (G14/D30)?

**Безопасность — ОБА направления**
- 🔴 Inbound: вход проходит `core/firewall`? Путь containment в `workspace/` (read И write/move/delete)?
- 🔴 Outbound: инструмент **выводит** данные клиенту? Тогда — не эхоит ли сырой `workspace/`-контент как доверенный (T1)? Деструктивный? → `destructiveHint` + confirm, не глухой блок (см. [[firewall-audit-2026-07-05]] D32).
- Описание/enum инструмента статичны (не из workspace/hot-reload)? (tool-poisoning T2)

**Хардкод / тесты / долгосрок**
- Магические значения (пути, пороги, имена листов, префиксы) вынесены в конфиг/реестр (`anti-hardcode`)? Ветка по типу или словарь-данные?
- Тест: happy + error/edge + adversarial; регрессия если чинит `D#`. Зрелость (honest-stub?).
- Через 6 мес: добавят соседнюю сущность — расширится данными или новым `if`?

## B. Баг-фикс

- 🔴 Баг **воспроизведён эмпирически** (реальный запуск, не гипотеза)?
- 🔴 Это уже известный `D#`/`G#`? (не переоткрывать, ссылаться)
- 🔴 Корневая причина, а не симптом? Почему возникло (проводка? конфиг не загружен D2? fail-open D10?)?
- Регресс-тест, который **падал ДО** фикса и проходит после, — написан и привязан к `D#`?
- Фикс не ломает соседнее поведение? Тесты `tests/quick/` зелёные?
- Решение→факт в commit + `docs/roadmap/_sessions.md`: что было, почему, вывод в правило?

## C. Рефакторинг

- 🔴 Поведение **точно не меняется** (иначе это не рефактор)?
- 🔴 Тесты зелёные ДО и после (прогнал оба раза)?
- Какую ось `code-quality` закрываю (арх-адеренс / parity / dead code / stringly-typed / altitude)?
- Не тяну ли логику в обёртку? Не переусложняю «на вырост»?
- Единичная минимальная правка или большой рефактор (тогда — план по шагам)?

## D. Security-аудит

- 🔴 Направление: **inbound** (атакующий→сервер) или **outbound** (сервер→клиент, T1–T7)?
- 🔴 Находка **доказана запуском** на `.venv` с реальным выводом? Severity 🔴🟠🟡⚪ по влиянию?
- Проводка правила проверена (не мёртвое, D8)? Конфиг реально загружен (D2)? Нет fail-open (D10)?
- Защита вообще **исполнима** для нашего сервера, или стережёт невозможное (нет SQL/shell/Windows — D33)? Не FP-генератор (D34)?
- Ремедиация с эталоном; для outbound — «провенанс, не фильтр»?
- Не переоткрываю существующий `D#`? Запись в `docs/roadmap/02_findings.md` + commit (`git log --follow core/firewall.md`?

## E. Тесты

- 🔴 Тест = **сценарий реального поведения**, не проверка кода/мок-на-отвяжись?
- 🔴 Поведенческий — против **живого сервера** (JSON-RPC `/mcp`), мок только истинно внешних провайдеров?
- Docstring ОДНОСТРОЧНЫЙ (5 вопросов продуманы → в commit)? Ассерт на контракт (`ToolResult`/код реакции), не truthy?
- 🔴 Ожидание объявлено НАМЕРЕНИЕМ, а не вычислено из конфига, по которому отвечает сервер (иначе тавтология — зелено на сломанном)?
- При провале печатается ФАКТИЧЕСКИЙ код отказа и причина из ответа, а не только «ожидал успех»?
- Это требование уже проверяет другой набор? (хозяин зоны — `tests/CATALOG.md §A–D`; дубль-ассерт = три красных на один дефект)
- В исходнике нет состояния процесса: статусов находок, «обнови CATALOG», истории «прежде было X»?
- Зрелость возможности: реализован / honest-stub (падает честно, не фейк-success) / запланирован (`xfail`-spec)?
- Изоляция: не зависит от порядка? Состояние firewall сброшено между тестами?
- Размещение: быстрый→`quick/` (удалить), постоянный→`tests/<name>/`+`history.md`?
- Покрытие: где дыры (capability-map по `tools/list`)? Adversarial и outbound-направление?

## F. Правка конфига (`config/*.yaml`)

- 🔴 Значение **реально грузится** кодом (эмпирика: правка → меняет поведение)? Или мёртвый knob (D35)/игнорируемый конфиг (D2)?
- Дефолт сохраняет прежнее поведение?
- Это декларация (место в конфиге верно) или логика (тогда не в конфиг)?
- Hot-reload: firewall.yaml/server_reactions.yaml подхватятся; меняется ли контракт, видимый клиенту (rug-pull T3)?
- Секрет в конфиге? → env/хранилище, не инлайн (D31, → `security-reviewer`); файл в `.gitignore`?

## G. Фронтенд студии (`.tsx`) — вступает в силу с первого компонента

- 🔴 Где это ЛЕЖИТ? Примитив, экран или слой доступа к серверу — три разных этажа (`project-conventions`). Компонент, который тянет данные, решает раскладку и рисует, — толстая обёртка.
- 🔴 Это ПЯТЫЙ похожий компонент или вариант существующего примитива? Пять карточек одного назначения = пять источников одной правды (`F99`/`F100` в UI).
- 🔴 Размер/отступ/шрифт/цвет/длительность — из токена? Проверка: «поменять размер карточки» = правка ОДНОГО значения без захода в `.tsx` (`anti-hardcode`).
- 🔴 Данные из `workspace/` попадают в РАЗМЕТКУ? Провенанс недоверенный, движок другой: `dangerouslySetInnerHTML`, `src`/`href` из данных (`security-reviewer`, раздел «Студия»).
- 🔴 Запись идёт через MCP-инструменты и по отпусканию, один вызов на жест? Второй бэкенд или поток правок — дефект, а не оптимизация (`20` §0 п. 1, §3).
- 🟠 `useEffect` здесь вообще нужен? Дерево решений ДО написания (`no-unnecessary-effects`).
- 🟠 Примитив отдаёт `data-component`? Без него «какой компонент это рисует» не отвечается (`20` §4б).
- 🟠 Что покраснеет, если инвариант нарушат? Сторожа `.tsx` нет — значит инвариант держит ТЕСТ (`test-master`), иначе он держится ничем.
- 🟡 Правишь существующий компонент → чем докажешь, что задето только заданное (`verified-edits` §3а/§3г)?
