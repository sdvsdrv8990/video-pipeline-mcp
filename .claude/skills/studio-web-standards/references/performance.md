# Скорость студии

Оглавление: цель и замер · бандл · перерисовки · раскладка и анимация · картинки и шрифты ·
списки · сервер и кеш · чего не делать.

## Цель и замер

Core Web Vitals, «хорошо» на 75-м перцентиле визитов (web.dev/articles/vitals):

| Метрика | Что меряет | Порог «хорошо» |
|---|---|---|
| LCP | когда показан самый крупный элемент первого экрана | ≤ 2.5 с <!-- снимок ок: внешний порог web.dev --> |
| INP | задержка отклика на жест за весь визит | ≤ 200 мс <!-- снимок ок: внешний порог web.dev --> |
| CLS | суммарный сдвиг раскладки без жеста | ≤ 0.1 <!-- снимок ок: внешний порог web.dev --> |

Студия — рабочее приложение, а не лендинг: главная метрика для неё INP (жест в таблице, фильтр,
переключение вкладки), а не LCP. Замер делается на СОБРАННОМ дереве (`vite preview`), не на
`vite dev` — в режиме разработки нет ни сжатия, ни разделения, и числа врут в обе стороны.

Лабораторный замер без внешних сервисов — Lighthouse (Apache-2.0) из той же Chromium, что у
Playwright; полевой — библиотека `web-vitals` (Apache-2.0), и отправлять её числа можно только
своему серверу: сторонняя аналитика — внешний получатель (условие владельца §4а).

## Бандл

- **Разделение по доменам.** Экран домена — `React.lazy(() => import(...))` под `Suspense` с
  честным состоянием загрузки. Первый экран не тянет код конкурентов и видео-проекта.
- **Бюджет объявляется**, а не держится памятью: вес начального чанка после сжатия фиксируется
  числом в репозитории и растёт только решением (тот же храповик, что потолки сторожей). Сборка
  печатает вес каждого чанка — это и есть улика.
- **Анализ состава** — `rollup-plugin-visualizer` (MIT) разово, когда бюджет трещит; в гейт не
  ставится.
- **Иконки**: `lucide-react` только именованными импортами. Динамический выбор «иконка по имени
  строкой» и `import *` отключают вытряхивание и тянут всю библиотеку.
- **Карты исходников** в продакшене не публикуются (или `hidden`): это и вес, и раскрытие кода.

## Перерисовки (INP)

- **Состояние живёт там, где читается.** В дизайне всё состояние навигации и модалок лежит в
  корневом компоненте — каждое нажатие клавиши в поиске перерисовывает всё приложение.
- **Производное считается при отрисовке**, а не хранится копией через эффект
  (`no-unnecessary-effects`): лишний эффект — лишний проход отрисовки.
- **Тяжёлый фильтр списка** — `useDeferredValue`/`startTransition`: ввод остаётся отзывчивым, список
  догоняет.
- **Мемоизация — по замеру, а не впрок.** React Compiler мемоизирует сам; ручные `useMemo`/
  `memo` везде — шум, который прячет настоящую причину. Профилировщик React DevTools показывает, что
  перерисовалось и почему.
- **Обработчик жеста не делает долгой работы синхронно**: задача длиннее 50 мс <!-- снимок ок: внешний порог — определение long task, W3C Long Tasks API --> блокирует ответ.

## Раскладка и анимация (CLS и плавность)

- Анимируются только `transform` и `opacity` — их считает композитор. `transition-all` анимирует и
  `width`/`height`/`padding` — каждый кадр пересчёт раскладки. Писать `transition-colors`,
  `transition-transform`, `transition-opacity`.
- Под место, которое заполнится позже (миниатюра, график, счётчик), резервируется размер —
  `aspect-ratio`, `min-height` скелетона того же размера.
- Шрифт, приехавший позже, не сдвигает текст (см. ниже).
- Длинные анимации уважают `prefers-reduced-motion` (`motion-safe:`).

## Картинки и шрифты

- У каждой `<img>` — `width`/`height` или класс с `aspect-ratio`; ниже первого экрана —
  `loading="lazy"` и `decoding="async"`; главная картинка первого экрана — без `lazy`, с
  `fetchpriority="high"`.
- Миниатюры приходят нужного размера (`srcset`/`sizes`), а не крупным кадром в маленькую карточку.
- Картинки по чужим адресам (стоковые фото в дизайне) — внешний получатель и точка отказа; в
  продакшене — только свой источник (`security-reviewer`, `img-src`).
- Шрифт сейчас системный — ноль загрузки. Если появится свой: `woff2` на своём сервере,
  подмножество (кириллица + латиница), `font-display: swap`, `preload` только одного
  начертания первого экрана, запасной шрифт с `size-adjust`, чтобы подмена не двигала текст.

## Длинные списки

Видео конкурента, комментарии, строки таблиц растут без предела. Сотни узлов DOM — медленная
отрисовка и прокрутка. Окно отрисовки — библиотекой (`@tanstack/react-virtual`, MIT), а не своим
расчётом; либо постраничность от сервера. Порог «когда нужно окно» — по замеру на реальном объёме,
а не заранее.

## Сервер и кеш

- Чтение одного и того же с сервера при каждом заходе на экран — это и задержка, и нагрузка на
  единственную дверь. Кеш чтений с явной инвалидацией по записи — библиотекой
  (`@tanstack/react-query`, MIT); свой кеш на `useEffect` — ровно то, что эта библиотека делает
  правильно (гонки, отмена, повтор, устаревание).
- Одинаковые параллельные запросы склеиваются, а не множатся.
- Опрос прогресса рендера — с интервалом, паузой на скрытой вкладке и остановкой на финальном
  статусе.

## Чего не делать

- Оптимизировать без замера — правка «для скорости» без числа до и после не принимается.
- Тащить тяжёлую библиотеку ради одной функции (форматирование дат, группировка) — у платформы
  есть `Intl.*`, у языка — встроенные методы в пределах пола браузеров.
- Прятать медленность за спиннером: спиннер — честное состояние загрузки, а не лечение.
