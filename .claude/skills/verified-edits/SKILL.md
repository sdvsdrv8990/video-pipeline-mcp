# Verified Edits

Правка считается сделанной, когда есть **доказательство**, что она попала в файл и дала эффект.
Не «скрипт отработал», не «я заменил строку» — вывод команды, который это показывает.

Причина существования скилла: самый дешёвый способ потерять час — тихий промах мимо якоря.
Скрипт печатает «готово», диффа нет, тесты локально зелёные, а падает CI через 3 минуты.

---

## 0. До первой правки — факты, а не самооценка

Вопрос «ты уверен?» бесполезен: модель отвечает «да» и правит дальше. Работает другое —
потребовать **конкретные факты**, которые нельзя предъявить, не запустив поиск. Сам поиск
меняет правку; уверенность не меняет ничего.

Перед первой правкой несущего файла (код сервера, декларации и сторожа — всё, что не `docs/` и не `workspace/`):

1. **Кто это читает/вызывает** — `grep -rn "<имя>" --include='*.py' core server.py tools tests`.
   Ноль вызывающих — это находка (мёртвая половина), а не разрешение править молча.
2. **Какой контракт задет** — `ToolResult`/`ErrorDetail`, код реакции в реестре, объявление
   в `config/*.yaml`. Контракт, видимый клиенту, меняется отдельным решением, а не попутно.
3. **Что здесь уже решено** — `git log --oneline -5 -- <файл>` + `docs/roadmap/02_findings.md`:
   не переоткрываешь ли закрытый `D#`/`F#`.
4. **Дословная инструкция владельца** — процитируй, не пересказывай.

Механически это требует хук `.claude/hooks/vpm-fact-gate.py`, и он наблюдает в двух точках,
потому что одной не хватает:

| Точка | Что видит | Что может |
|---|---|---|
| `PreToolUse` | НАМЕРЕНИЕ: `Edit`/`Write`/`MultiEdit` по несущему файлу, разрушительная команда | **предотвратить** — отказ до действия |
| `PostToolUse` | ЭФФЕКТ: что реально стало грязным в `git` после `Bash` | **заметить** — запись уже произошла |

Вторая точка существует потому, что правка через оболочку (heredoc, `tee`, перенаправление,
`python - <<PY`) проходит мимо инструментов `Edit`/`Write`.

**Граница проходит по ЛИТЕРАЛАМ, а не по форме команды** — это замерено, а не предположено, и
проверено на ВСЕХ формах запуска: heredoc, `-c`, перенаправление. До S26 форма всё же двигала
границу — литерал внутри `python3 -c` не разрешался вовсе; теперь разрешается.
До записи разрешаются и потому судятся: прямой `Path("путь")`/`open("путь")`, запись через
связанное имя, перенаправление `>`/`>>` и путь, СОБРАННЫЙ склейкой литералов
(`корень = Path("core")`, `цель = корень / "engine" / "engine.py"`). Не разрешается — и не может:
путь, вычисляемый из ДАННЫХ (f-строка с переменной, глоб, значение функции, элемент цикла).

**Для вычисляемого пути контракт объявлен «постфактум»**, и это решение, а не недосмотр: гейт,
который ловит 80% и выглядит как 100%, отменяет проверку глазами, а угадывать вычисляемое значит
плодить ложные цели. Правишь несущий файл по вычисляемому пути — предъявляй факты САМ, до запуска;
хук здесь только заметит, и уже после записи. Нужно предупреждение — напиши путь литералом.

Граница, которую надо держать в голове: **Pre предотвращает, Post лишь замечает**. Для гейта
фактов это почти равноценно (поиск всё равно происходит до следующего шага), для разрушительной
команды — нет, и там работает только Pre. Обе точки не знают, предъявил ты факты или просто
повторил вызов: хук — напоминание, настоящий гейт — CI. Выключатель — `VPM_FACT_GATE=off`.

## 1. Промах обязан быть громким

| Примитив | Что делает при несовпадении | Когда можно |
|---|---|---|
| `Edit` | **ошибка** — правка не применяется | по умолчанию для любого файла |
| `python str.replace` | молча возвращает исходник | только с `assert old in src` |
| `sed -i s/…/…/` | молча ничего не меняет, exit 0 | только с проверкой after-состояния |
| перезапись файла целиком | теряет чужие правки | когда файл прочитан целиком в этой сессии |

Батч-скрипт оправдан, когда правок много и они механические. Тогда он обязан падать сам:

```python
for path, old, new in EDITS:
    src = Path(path).read_text()
    assert old in src, f"ЯКОРЬ НЕ НАЙДЕН: {path}: {old[:60]!r}"   # без этого промах немой
    Path(path).write_text(src.replace(old, new, 1))
```

Без `assert` батч — это `Edit` с отключённой диагностикой. Ради экономии одного вызова
инструмента ты меняешь громкую ошибку на тихую. Никогда не окупается.

## 1б. Три способа принять провал за успех (все три случились)

Есть и обратная ошибка, и она стоит чужого хода: **заказанный красный неотличим от настоящего.**
Проба, которая ОБЯЗАНА покраснеть (слепота оси, мутация проводки, регрессия до фикса), приезжает в
ленту как `Error: Exit code 1`, и владелец читает её как твой промах. Объявляй ожидание в самой
команде — и подписывай её, чтобы объявление пережило сессию:

```bash
проба; echo "exit=$?"
python3 scripts/guards/_stamp.py --kind проба --role УЛИКА \
  --what "ось слепа к core/ — ruff ОБЯЗАН покраснеть" --intent форма-правки \
  --expected red --actual red --cmd "ruff check core/advice.py"
```

**Урок, вынесенный из прогона, обязан унести с собой ключ.** Ставь его меткой `⟨улика: ⟦vpm КЛЮЧ⟧⟩` рядом с `⟨исполняет: …⟩` в реестре уроков: первая ведёт в прогон, где урок родился, вторая называет механизм, который ловит повтор. Обе судят оси `урок без ключа улики` и `урок без механизма`, и потолки идут только вниз.

Подпись печатает две строки (роль и ключи) и кладёт запись; любой, кому строку показали потом,
поднимает её одной командой — `reproduce.py --stamp <ключ>` — вместо повторного дознания. Красный
без объявления и без подписи — молчаливое «я сломал», и стоит он чужого хода.

- **`cmd && echo "ok"` при провале МОЛЧИТ.** Отсутствие «ok» не бросается в глаза так, как красная
  строка: пять ошибок `ruff` были прочитаны как успех, и восьмиминутная сборка ушла впустую. Печатай
  код явно: `cmd; echo "exit=$?"`.
- **`$?` после конвейера — код ПОСЛЕДНЕЙ команды.** `проверка | tail` всегда даёт ноль. Либо без
  конвейера, либо `${PIPESTATUS[0]}`.
- **`sed -i 'Nс/…'` по номеру строки промахивается молча.** Ошибся на единицу — правка не легла,
  команда вернула ноль. Якорь брать текстом и подтверждать `git diff --stat`; для мутации это
  критично: не легла — значит зелёный прогон не значит НИЧЕГО.

## 2. Якорь — из свежего чтения, а не по памяти

Копируй байты из вывода `Read`/`grep` **этого** сеанса, не набирай приблизительно.
Классический промах: в файле `"pytest>=8.0",`, в скрипте написано `"pytest>=8",` — глазами
одно и то же, для `replace` разные строки. То же с пробелами, кавычками (`"` vs `«`),
переносами, отступами YAML, невидимой запятой в конце.

Если якоря нет под рукой — сначала `grep -n` по уникальному куску, потом правка по тому,
что вернул grep. Дешевле, чем разбирать красный CI.

## 3. Пост-условие на КАЖДЫЙ тронутый файл

Скрипт правит три файла — проверяй три, а не один. Безусловный `print("обновлено")`
доказывает только то, что интерпретатор дошёл до конца.

Минимальный набор после правки:
- `git diff --stat` — файлы вообще изменились? (пустой дифф = правка не применилась);
- `grep -n "<новое>" <каждый файл>` — попало именно то, что хотел;
- прогон теста/линтера зоны — эффект не сломал соседей.

**Символ и его импорт — ДВЕ независимые замены, и вторая промахивается молча.** Вставленный блок
использует имя, а `import` кладётся своим `replace` по своему якорю: не попал — файл собран из двух
верных половин и не работает. `git diff` показывает обе правки, пост-условие «якорь лёг» проходит,
а видит промах только линтер (`F821` — имя без импорта, `F401` — импорт без имени). Отсюда правило:
**обещал импорт — проверь, что он в файле есть**, тем же прогоном, что и якорь.

Механика этого не оставлена на дисциплину: шим `.claude/hooks/vpm-invariants.py` стоит `PostToolUse`
на `Write|Edit|MultiEdit` И на `Bash` и после КАЖДОЙ правки судит форму того, что она оставила в
дереве — компиляция плюс линтер проекта по незакоммиченным `.py`. Правка скриптом идёт мимо `Edit`,
поэтому файлы берутся из дерева, а не из события. Опережать его дешевле, чем разбирать четыре
немых промаха разом; **своего помощника правки заводить не нужно** — проверка живёт в сторожах,
которые переживают сессию, а приватный скрипт в скратчпаде не судит никто.

### 3а. «Я трогал только X» — заявка, пока не предъявлен РАЗБОР

Чтение диффа глазами не доказывает, что задето только то, что задумано: батч на 300+ строк
глазами не проверяется. Доказывай парсером, и на ВСЕХ файлах сразу:

- **Правил только текст (комментарий/докстринг)** → сравни потоки токенов до и после
  (`tokenize`), выбросив `COMMENT`/`NL` и заменив голые строки-выражения на маркер. Совпали —
  код не менялся побайтово, и это факт, а не впечатление.
- **Правил комментарии в декларации** (`config/*.yaml`, `pyproject.toml`, `ci.yml`) → загрузи
  `yaml.safe_load_all` / `tomllib.loads` до и после и сравни ОБЪЕКТЫ. Комментарии туда не
  попадают, поэтому равенство = ни один порог, код реакции или правило не сдвинулись.
  Для `.sh`/`.gitignore` — сравнение строк, из которых выброшены строки-комментарии.
- **Расхождение обязано быть ИМЕНОВАННЫМ.** Отчёт «расхождений: 2» бесполезен: назови файлы и
  сверь со списком того, что менял намеренно. В этой сессии так отличилась ваша незакоммиченная
  работа от моей правки — и это спасло от ложного «я ничего не ломал».

### 3г. Правка `.tsx`: чем доказывать, что задето только заданное

Три беды правки React (`20` §4б) — снесённая анимация, тронутые иконки, «не понять, какому
компоненту это принадлежит» — сводятся к одной: правка не была изолирована и не была разобрана.
Приёмы §3а переносятся целиком, меняется инструмент доказательства:

- **правил разметку/текст** → `tsc --noEmit` до и после ловит расхождение типов, но НЕ увидит
  снятый класс или исчезнувший пропс. Прямой аналог «сравни потоки токенов» — сверка СПИСКА
  отрисованных `data-component` и их атрибутов до и после: подпись примитива (`20` §4б) заведена
  ровно затем, чтобы такой разбор был возможен;
- **правил токен** → эффект отложенный по определению: он не там, где правка, а во всех местах
  потребления (§5). Пост-условие — перечислить ВСЕ места и убедиться, что поехали все, а не первое;
- **«анимацию снесло и не восстановить»** — это не про ИИ, а про коммит: восстанавливает `git`,
  когда правка изолирована. Несколько смыслов в одном коммите = откатывать точечно нечего.

### 3б. Автозамена по регэкспу калечит текст тихо

Правило вида «убрать пробел перед пунктуацией» съедает пробел и перед `.env`, `.xlsx`, `.venv`.
Ищи урон ОТДЕЛЬНЫМ детектором, а не перечитыванием: пройди пары (старая строка → новая) и
отметь места, где пунктуация прилипла к следующему слову, а в оригинале там был пробел, плюс
строки, начинающиеся с осиротевшей пунктуации. Три таких места на 265 правок — норма, и глазами
их не находят. Отдельно: автоматическая заглавная буква после снятого префикса калечит
идентификаторы (`state_manager` → `State_manager`) — проверь `^#\s*[A-Z][a-z]+_`.

## 3в. Слияние и cherry-pick теряют ТЕЛО молча

`git cherry-pick` сопоставляет куски текста, а не смысловые единицы. Если заголовок раздела совпал
с чем-то в целевой ветке, а тело — нет, конфликт закончится на заголовке: раздел останется, тела
не будет, и `git status` доложит успех. В журнале сессий это выглядит как запись без содержимого.

**Пост-условие после каждого разрешённого конфликта — не «маркеров нет», а «каждый раздел несёт
тело»:**

```
grep -rn '^<<<<<<<\|^=======\|^>>>>>>>' <файлы>          # маркеров быть не должно
# длина каждого раздела у себя и у источника — числа обязаны совпасть:
awk '/^### /{name=$0; next} {n[name]++} END{for (k in n) print n[k], k}' <файл> | sort -n | head
git show <коммит>:<файл> | awk '/^### /{name=$0; next} {n[name]++} END{for (k in n) print n[k], k}' | sort -n | head
```

Раздел, всплывший наверх с нулём или парой строк, — кандидат на потерянное тело. Разошлось — доставай `git show <коммит>:<файл>`,
а не переписывай по памяти: перепись теряет пруфы, которых у тебя уже нет.

**`--ours`/`--theirs` — это выбор файла целиком, а не разрешение конфликта.** Флаг уместен, когда
одна из версий заведомо новее ПО ВСЕМУ файлу. Там, где у одной стороны свежее число, а у другой
подробнее описание, разрешать надо по содержанию: взять описание из одной, статус из другой.

**Ветку не мержат, не посмотрев, чем она отличается.** `git log <ветка> --not main --oneline`
покажет и то, что уже применено под другим хешем (перенесённый коммит), — мерж переиграл бы его
заново. Один нужный коммит переносится cherry-pick'ом, а не мержем всей ветки.

## 4. Гейт перед заявлением «сделано»

Идея из `obra/superpowers` (`verification-before-completion`) и рекомендации Anthropic
встраивать детерминированную проверку в сам процесс, а не оставлять её на усмотрение:

1. назови команду, которая **докажет** утверждение;
2. прогони её свежо в этой сессии;
3. прочитай вывод целиком, включая exit-код;
4. сверь: вывод действительно подтверждает утверждение?
5. только теперь заявляй — вместе с этим выводом.

Формулировки «должно работать», «вроде поправил», «скорее всего зелёное» — сигнал, что
шаг 2 пропущен. Правка без диффа — не правка.

**Сама проверка тоже обязана быть проверена.** Ловушка, стоившая ложного «OK» (S24): в
`cmd | filter` конструкция `${PIPESTATUS[0]}` берёт статус ПЕРВОГО звена — если первым стоит
`echo`, меряется `echo`, и любой результат выглядит успешным. Ставь проверяемую команду первой,
либо мерь без конвейера (`cmd >/dev/null 2>&1; echo $?`), либо `set -o pipefail`. Признак, что
измеряешь не то: все случаи «прошли», включая заведомо ломаный.

**Жёсткая форма правила: не прогнал проверку В ЭТОМ ходе — не имеешь права утверждать, что она проходит.**
Прогон десять сообщений назад не считается: между ним и твоим утверждением лежат твои же правки.
Что чем доказывается — и что НЕ считается доказательством:

| Утверждение | Доказывает | НЕ доказывает |
|---|---|---|
| «тесты зелёные» | вывод набора с exit-кодом в этом ходе | «правил только доки» · зелёный прогон до правки |
| «гейт зелёный» | exit-код КАЖДОЙ из семи джоб `ci.yml` | один `pytest` · «локально же работало» |
| «правка применилась» | `git diff` / пост-условие на файл | «инструмент не сообщил об ошибке» |
| «CI прошёл» | `gh run list` со статусом на ТВОЁМ коммите | зелёный прогон предыдущего коммита |
| «дефекта больше нет» | мутация: откат фикса красит тест | тест зелёный после фикса |

### 4б. `pre-commit` здесь ищет инструменты в PATH, а не в проекте

Хуки объявлены как `language: system` — они зовут `ruff`/`mypy` из окружения. Коммит из оболочки
без активированного виртуального окружения падает на «Executable not found», и это **не заключение
о качестве кода**: проверка не состоялась вовсе. Активируй окружение перед `git commit`, иначе
получишь красный вывод там, где всё зелёно, и соблазн обойти хук флагом.

Обратная сторона: хук гоняется по РЕПОЗИТОРИЮ, а не по staged-файлам, поэтому он ловит и то, что
ты внёс в соседний файл и не собирался коммитить сейчас. Красный хук на «чужом» файле — сигнал
проверить свои же правки, а не повод исключить файл.

## 4б. Гейт больше не верит словам — он смотрит на вещь

Проверки в этом проекте перестроены так, что «сказал» и «сделал» различаются механически:

| Заявление | Чем проверяется |
|---|---|
| «гейт зелёный» | Stop-хук САМ гонит дешёвые джобы (ruff, mypy, comment-guard, invariants, findings_count) — 2–3 с — и блокирует с их выводом, если реальность разошлась |
| «поведение проверено» | последняя строка журнала `tests/.journal/scenarios-*.jsonl` (`__run__`): обязана быть СВЕЖЕЕ последней правки кода, зелёной и покрывать задетые сценарии. Нет — хук гонит задетое сам |
| «я разобрался, прежде чем править» | между отказом гейта фактов и повтором правки обязан лежать след разведки (`grep`, `git log`, чтение). Иначе повтор отклоняется снова |

Следствие для работы: **прогоняй сам и до заявления.** Хук всё равно перепроверит, но его блокировка
стоит хода, а твой прогон — секунд. И наоборот: не заявляй зелёное «по ощущению» — разойдётся.

**Пишешь нового сторожа — проверяй ВЕЩЬ, а не её след в переписке.** Regex по стенограмме
удовлетворяется командой, запущенной часом раньше правки, и ничего не знает ни о её исходе, ни об
относимости. Улика — артефакт на диске с временем: журнал прогона, mtime файла, коммит, вывод с
exit-кодом. Контракт «по умолчанию ПРОВАЛ»: критерий считается непройденным, пока улика не открыта
(паттерн `anthropics/cwc-long-running-agents`).

## 4а. Формулировки, которые выдают пропущенный прогон

Эти обороты почти всегда стоят на месте невыполненной проверки — увидел у себя, вернись к шагу 2:

«должно работать» · «вроде поправил» · «скорее всего зелёное» · «локально проходит» ·
«это pre-existing» · «тесты потом» · «мутация выжила — значит фикс лишний» (нет: значит тест не
добивает до механизма) · «в CI, наверное, так же».

Stop-хук `.claude/hooks/vpm-delivery-gate.py` ловит машинную часть этого: заявление о зелёном,
когда в стенограмме сессии нет ни одного прогона раннера, и сложную сессию (>=3 правок) без
записи решение→факт. Выключатель — `VPM_DELIVERY_GATE=off`.

## 5. Отложенный эффект: проверяй там, где эффект

Самый коварный класс — правки, чей результат виден не там, где ты их сделал:

| Правка | Локально молчит, потому что | Чем проверить |
|---|---|---|
| зависимость/extras в манифесте | пакет уже стоит в твоём окружении | `pip install -e ".[dev]" --dry-run`, чистый venv/контейнер |
| CI-workflow | локально workflow не исполняется | `gh run list` / `gh run view --log-failed` после пуша |
| `.gitignore` | файлы уже лежат на диске | `git check-ignore -v <path>`, `git ls-files` |
| конфиг с флагами | код может ключ игнорировать | поменять значение и увидеть **изменение поведения** в тесте |
| путь/переменная окружения | у тебя они уже выставлены | прогон в окружении без них |

Общее правило: **«зелено у меня» ≠ «зелено из чистого клона»**. Если правка адресована
другому окружению — доказательство берётся оттуда, иначе доказательства нет.

## 6. Когда правка касается конфига-с-выключателем

Отдельная ловушка: конфиг объявляет флаг, а код его не читает. Правка «выключил» проходит,
поведение не меняется, все тесты зелёные — потому что менять было нечему. Проверка одна:
поменяй значение и убедись, что **поведение стало другим**; если нет — это не твоя правка
не сработала, это мёртвая декларация, и она сама по себе находка.

---

## Разрушительное — отдельной командой, а не в связке

`проверка; echo; rm файл; проверка` в одной строке стоит дороже, чем кажется: связку обязан
разобрать классификатор безопасности, и когда он недоступен, не выполняется НИЧЕГО — включая
безобидную половину. Тот же приём поднимает гейт фактов, и вместо работы идёт объяснение.

**Правило:** удаление, перемещение, перезапись — своим вызовом, после того как посмотрел на цель
(`ls`, `git status`). Проверки и замеры — своим. Это не осторожность ради осторожности: склеенная
команда теряется целиком по причине, не имеющей отношения к делу.

## Оболочка — только ASCII: чужая буква в имени переменной молча создаёт файл

Имена переменных bash берёт из ASCII, поэтому `$ДОМ` для него не подстановка: доллар и буквы
доезжают до команды БУКВАЛЬНО. `git clone . "$К"` создаёт каталог с именем `$К`, а `HOME="$ДОМ"`
уводит состояние хука в такой же каталог внутри репозитория. Так в корне дважды появлялся мусор,
отката у которого нет — файлов этих в git никогда не было.

Симптом узнаётся по выводу: строка вида `0$error` или путь, в котором доллар остался буквой, —
это не опечатка вывода, а несостоявшаяся подстановка.

**Правило (директива владельца 2026-09-06):**

- имя переменной — латиницей: `KLON=…`, дальше `"$KLON"`;
- русский путь или текст — ЗНАЧЕНИЕ в кавычках, а не имя: `grep -n 'остаток' file.py` законен;
- сомневаешься — не заводи переменную вовсе: подставь путь целиком, он длиннее, но переживёт;
- **в коде на Python кириллица законна** и этим правилом не задета — у нас ею названы половина
  функций сторожей. Речь только об ОБОЛОЧКЕ.

Держит правило гейт фактов (`vpm-fact-gate.py`, `SHELL_NON_ASCII`): отказ приходит ДО запуска и
называет пойманный кусок. Судится КЛАСС — не-ASCII в трёх позициях имени (подстановка,
присваивание, слово вроде `unset`/`for`, забирающее имя), — а не перечень алфавитов: украинская
«і» и греческий ломают оболочку так же. Тела here-document снимаются: питон с русскими именами
законен. Как пишется такая проверка вообще — `test-master`, раздел «по КЛАССУ нарушения».

## Constraints

### MUST DO
- Использовать `Edit` по умолчанию; батч/`sed` — только с `assert`/проверкой after-состояния.
- Брать якорь из свежего вывода `Read`/`grep`, а не из памяти.
- Проверять пост-условие на каждом тронутом файле + `git diff --stat`.
- Перед словом «сделано» — прогнать команду-доказательство и привести её вывод.
- Для правок с отложенным эффектом — проверять в целевом окружении (чистый venv, CI, clean clone).

### MUST NOT DO
- Печатать «готово» безусловно и считать это подтверждением.
- Заявлять результат по факту запуска скрипта, а не по факту диффа/прогона.
- Править то, чего не прочитал в этой сессии.
- Чинить симптом (дописать вызов) вместо промаха (якорь не совпал) — сначала пойми, почему не попало.
